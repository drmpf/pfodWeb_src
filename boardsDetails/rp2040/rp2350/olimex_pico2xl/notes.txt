PER-PIN REASONING

GPIO25 (PIN_LED / User_Led):
  capabilities: ["digital_output", "pwm_output", "led_high"]
  Onboard user LED (green, 0603), active-high (see schematic detail above).
  digital_input dropped, matching this repo's established led_high/led_low
  convention for dedicated onboard LED pins (see rpipico2/board.json GPIO25
  precedent - the direct RP2350A sibling of this board, same LED-GPIO
  number). pwm_output kept since arduino-pico's analogWrite() works on any
  RP2350 GPIO (enables LED brightness dimming). No SPI/I2C bus alias
  collision on GPIO25 in this board's own pins_arduino.h (Wire0/Wire1/SPI0/
  SPI1 pins are GPIO4-5, 12-19, 26-27 - GPIO25 is untouched), so no
  build_boards.js bus-capability contamination is possible here.

All other GPIOs: no chipGpios entry added. No button alias exists in this
board's pins_arduino.h to tag, and the only physical buttons (BOOT/BOOTSEL,
RESET) are out of this audit's GPIO-based tagging scope - BOOTSEL enters
the RP2350's ROM bootloader (not a normal digitalRead()-able GPIO in
Arduino) and RESET is a hardware reset line, not a GPIO at all. Same
out-of-scope rationale already established for this board's RP2350A
sibling (rpipico2/board.json) and the original RP2040 rpipico board. No
NeoPixel present on this board (confirmed absent from the official user
manual's LED-connection documentation) - no led_neopixel tag added.

BUG CHECK: No SPI/I2C alias collision found on the LED pin (GPIO25) or any
other pin in this board's pins_arduino.h relative to its own Wire0/Wire1/
SPI0/SPI1 definitions. No #define lines were removed or modified - this
board's pins_arduino.h is unchanged.

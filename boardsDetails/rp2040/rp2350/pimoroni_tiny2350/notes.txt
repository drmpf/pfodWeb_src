PER-PIN REASONING
- GPIO18/19/20: Confirmed by TWO independent, corroborating sources (pishop.us current product
  page text, and forums.pimoroni.com's own working sample code) to be a single onboard RGB LED
  (active-low), NOT three separate single-color LEDs and NOT the plain single-color LED the
  PIN_LED alias name might suggest — identical GPIO numbering, polarity, and marketing wording
  to the confirmed RP2040 sibling (pimoroni_tiny2040). GPIO19 is the specific channel this
  board's pins_arduino.h aliases as PIN_LED/LED_BUILTIN (its own header comment: "Use the Green
  LED element on pin 19 as LED_BUILTIN"). Tagged using this repo's per-channel RGB vocabulary:
    GPIO18: ["digital_output", "pwm_output", "led_r_low"]
    GPIO19: ["digital_output", "pwm_output", "led_g_low"]  (PIN_LED / LED_BUILTIN)
    GPIO20: ["digital_output", "pwm_output", "led_b_low"]
  pwm_output kept on all three — vendor docs explicitly describe PWM-dimming these pins.
  digital_input dropped, matching this repo's led_high/led_low/led_r_*/led_g_*/led_b_*
  precedent for dedicated onboard LED pins (including the Tiny 2040 sibling).

- GPIO23: NOT declared anywhere in this board's pins_arduino.h (no PIN_BUTTON alias), but
  confirmed via current vendor/reseller product pages ("GPIO Pin: GP23", "Logic: active low",
  "use the BOOT button as a user switch") to be a real, user-readable GPIO wired to the board's
  physical BOOT switch — distinct from the separate reset button, which the same product pages
  describe as a separate feature (drives RUN/hardware-reset directly, not a GPIO, matching the
  out-of-scope RESET rationale already used elsewhere in this repo, e.g. rpipico2/board.json,
  pimoroni_tiny2040/board.json). Added purely via a chipGpios entry (the general "GPIO absent
  from pins_arduino.h but present in chipGpios" mechanism already exercised for the Tiny 2040's
  GPIO23). Tagged ["digital_input", "button"] — digital_output/pwm_output deliberately OMITTED:
  no source retrieved in this session spells out that it is electrically safe to drive this
  BOOT/DFU-select line as an output (the Tiny 2040's own datasheet PDF explicitly called this
  circuit "diode"-protected, and the Tiny 2350's marketing copy reuses the identical "clever
  circuitry that lets you use the boot button as a user controllable switch" phrase, strongly
  implying the same protection mechanism, but no Tiny-2350-specific source spelled out the word
  "diode" itself). The conservative choice — input+button only — matches the Tiny 2040
  precedent and this repo's established pattern for BOOT-select-multiplexed pins (u-blox
  EVK-NORA-W10 GPIO0/SW2 in variants/esp32/esp32s3/nora_w10/board.json).

BUS-COLLISION CHECK (per task's specific hint re: SDA/SCL/SS/MOSI/MISO/SCK auto-append bug)
This board's own pins_arduino.h declares:
  PIN_SPI0_MISO=4, PIN_SPI0_MOSI=7, PIN_SPI0_SCK=6, PIN_SPI0_SS=5
  PIN_SPI1_MISO=28, PIN_SPI1_MOSI=27, PIN_SPI1_SCK=26, PIN_SPI1_SS=29
  PIN_WIRE0_SDA=12, PIN_WIRE0_SCL=13, PIN_WIRE1_SDA=6, PIN_WIRE1_SCL=7
None of these values (4, 5, 6, 7, 12, 13, 26, 27, 28, 29) coincide with the confirmed RGB
LED/button pins 18, 19, 20, or 23. So build_boards.js's unconditional SS/SDA/SCL/MOSI/MISO/SCK
alias auto-append never fires on any tagged pin here — no pins_arduino.h edit needed on this
board (unlike the adafruit_feather_scorpio precedent, where a vendor-default SPI0_SS value did
collide with that board's confirmed onboard LED pin).

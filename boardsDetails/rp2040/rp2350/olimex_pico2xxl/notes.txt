Board: olimex_pico2xxl (chip bucket: rp2040/rp2350)
Vendor: Olimex "RP2350-PICO2-XXL" — RP2350B-based, all 48 GPIO broken out,
16MB QSPI flash, 8MB QSPI PSRAM, USB-C, BOOT+RESET buttons, Qwiic/Stemma QT,
pUEXT connector, microSD slot. Larger/XXL sibling of olimex_pico2xl (2MB
flash, no PSRAM/SD) and olimex_pico2bb48 (breadboard-friendly variant).

Per-pin reasoning
------------------
GPIO25 (PIN_LED)
  - Tagged: ["digital_output", "pwm_output", "led_high"] (digital_input
    dropped, per established led_high/led_low precedent for dedicated
    onboard LED pins — see rp2040/rp2350/rpipico2 GPIO25).
  - Active-HIGH: schematic shows GPIO25 -> R15 (2.2k series resistor) ->
    LED1 -> GND, i.e. GPIO25 sources current into the LED to ground when
    driven HIGH.
  - No alias collision: this board's own pins_arduino.h defines
    PIN_SERIAL1_TX/RX=0/1, PIN_SERIAL2_TX/RX=8/9, PIN_SPI0=16/19/18/17,
    PIN_SPI1=12/15/14/13, PIN_WIRE0=4/5, PIN_WIRE1=26/27 — GPIO25 does
    not appear in any of these, so build_boards.js's automatic bus-
    capability append cannot contaminate this pin. No fix needed for
    that bug class on this board.

No button found on any numbered GPIO
  - BOOT and RESET are both dedicated hardware lines (QSPI flash CS and
    chip RUN/reset respectively), not GPIO — confirmed via schematic (see
    above) and consistent with every other plain (non-W) RP2040/RP2350
    Pico-family board already audited in this repo (e.g. rpipico2).
    inputOnlyGpios left empty; no "button" capability tag applied
    anywhere — out of scope for GPIO-keyed capability tagging, not a
    missed tag.

No onboard NeoPixel/WS2812
  - Not mentioned in any vendor source (Olimex product page, GitHub
    README, schematic). Board has exactly one green status LED (LED1,
    GPIO25) plus the two non-GPIO buttons. No NeoPixel tag applied.

GPIO8 / PSRAM_CS observation (informational only, no action taken)
  - This board's pins_arduino.h defines both `#define RP2350_PSRAM_CS 8`
    and `#define PIN_SERIAL2_TX (8u)` — i.e. GPIO8 is nominally both the
    PSRAM chip-select and a Serial2 TX alias. The schematic's bus_alias
    confirms GPIO8 is physically "QMI_CS1n" (QSPI memory-interface CS),
    consistent with PSRAM use. This is a vendor arduino-pico header
    quirk (Serial2 on GPIO8/9 is likely unusable while PSRAM is active),
    not a button/LED/SDA/SCL/SS/MOSI/MISO/SCK collision, so it falls
    outside this audit's defined bug class. Left unmodified; flagged here
    for visibility only.

Summary
-------
Created variants/rp2040/rp2350/olimex_pico2xxl/board.json (full file,
chip-level defaults copied verbatim from variants/rp2040/rp2350/
board.json, plus one chipGpios entry): GPIO25 tagged
digital_output+pwm_output+led_high (onboard green status LED,
active-high, schematically confirmed via 2.2k series resistor to GND).
No button or NeoPixel capability applied — BOOT/RESET are non-GPIO
hardware lines and no NeoPixel exists on this board. No bus-alias
collision found on GPIO25, so no #define removal was needed in
pins_arduino.h.

Board: iLabs "Challenger RP2040 UWB (DWM3000)" (chip bucket: rp2040)
Directory: variants/rp2040/rp2040/challenger_2040_uwb/
Audit date: 2026-07-13

SUMMARY
-------
Confirmed the onboard DWM3000 Ultra-Wideband module (integrates a Qorvo
DW3110 chip, used for indoor positioning/ranging) occupies GPIO9-15:
SPI1 bus (SS=9, SCK=10, MOSI=11, MISO=12) plus three dedicated control
lines (RESET=13, active-low; IRQ=14; WAKEUP=15). Found these pins were
ALREADY fully excluded from the Designer's pin list by this board's
existing pins_arduino.h (no static const uint8_t alias declared for any
of them, and the file already carries a prior-session "pfodWeb NOTE"
documenting this, including an explicit note that GPIO18/D17 is NOT
DWM3000-dedicated on this board unlike the sibling LoRa/SubGHz boards) --
so no board.json chipGpios entries were needed or added for the radio
pins themselves. Created board.json (this board previously had none)
containing a single chipGpios entry: GPIO24 (D18/PIN_LED/LED_BUILTIN),
tagged as the onboard general-purpose green user LED, confirmed
active-high directly by this board's own official iLabs datasheet (no
cross-reference needed, unlike the challenger_2040_subghz/nfc siblings
whose own datasheets omitted the active level). No onboard NeoPixel or
user pushbutton found. pins_arduino.h was NOT modified this session
(already correct -- GPIO9-15 have no D-alias, GPIO18/D17 correctly left
available, GPIO24 has no colliding SPI/I2C bus alias so the
build_boards.js bus-auto-append bug class does not apply here).

WHY NO chipGpios ENTRIES FOR THE DWM3000 PINS (GPIO9-15)
-----------------------------------------------------------
Same mechanism as challenger_2040_lora/challenger_2040_subghz:
buildEsp32Board() (the parser the "rp2040" family routes through) only
lists a GPIO in the Designer's pin picker if it appears either (a) as a
`static const uint8_t` alias in pins_arduino.h, or (b) as a key in this
file's chipGpios object. Since this board's pins_arduino.h already
declares NO alias at all for GPIO9, 10, 11, 12, 13, 14, or 15, those
GPIOs are already 100% absent from the Designer's pin list with no
board.json changes required. Adding chipGpios entries for them here
would be COUNTERPRODUCTIVE: it would re-add each one to allGpios as a
bare, visible "GPIO<n>" row carrying an auto-appended "Check if
available on board" note -- undoing the full concealment the
pins_arduino.h aliasing (or lack thereof) already achieves, and
misleadingly suggesting the pin's availability is merely unverified
rather than physically dedicated to the UWB module. Left alone.

PER-PIN REASONING
------------------
GPIO9  - DWM3000_SS / PIN_SPI1_SS -- DWM3000 module's dedicated SPI1
         chip-select line. No D-alias exists; already excluded. No
         chipGpios entry added (see rationale above).
GPIO10 - PIN_SPI1_SCK -- DWM3000 module's dedicated SPI1 clock line. No
         D-alias exists; already excluded. No chipGpios entry added.
GPIO11 - PIN_SPI1_MOSI -- DWM3000 module's dedicated SPI1 MOSI line. No
         D-alias exists; already excluded. No chipGpios entry added.
GPIO12 - PIN_SPI1_MISO -- DWM3000 module's dedicated SPI1 MISO line. No
         D-alias exists; already excluded. No chipGpios entry added.
GPIO13 - DWM3000_RST -- DWM3000 module's active-low reset line, driven
         by the RP2040. No D-alias exists; already excluded. No
         chipGpios entry added.
GPIO14 - DWM3000_IRQ -- DWM3000 module's interrupt line to the RP2040.
         No D-alias exists; already excluded. No chipGpios entry added.
GPIO15 - DWM3000_WAKEUP -- DWM3000 module's sleep/wake control line. No
         D-alias exists; already excluded. No chipGpios entry added.
GPIO18 - D17 -- confirmed (by this board's own pins_arduino.h comment
         and independently by the iLabs datasheet's silence on GPIO18
         for this board) NOT DWM3000-dedicated on this board, unlike the
         challenger_2040_lora/subghz siblings where GPIO18 is a DIO2
         interrupt line. Stays available as a plain general-purpose pin
         with default full capabilities; no chipGpios entry needed.
GPIO24 - PIN_LED / LED_BUILTIN (D18 alias) -- onboard general-purpose
         user green LED. Confirmed present, on pin D18, and active-high
         directly by the official iLabs datasheet ("user programmable
         green LED... connected to pin D18 (BUILTIN_LED)", active-high
         standard logic) -- no cross-reference to a sibling board needed
         since this board's own datasheet states the active level
         explicitly. Tagged
         ["digital_output","pwm_output","led_high"]: digital_input
         dropped to match this repo's established led_high precedent for
         dedicated onboard LED pins; pwm_output kept since arduino-pico's
         analogWrite() works on any RP2040 GPIO, enabling brightness
         dimming. GPIO24 carries no SPI/I2C/other bus alias on this
         board (only D18), so the build_boards.js unconditional
         bus-capability auto-append (the "confirmed button/LED pin also
         aliased as SDA/SCL/SS/MOSI/MISO/SCK" bug class flagged for this
         audit) does not apply here -- no pins_arduino.h edit was needed.

NO NEOPIXEL FOUND
------------------
Confirmed absent by both the iLabs datasheet and product page (neither
mentions one), and confirmed absent from the upstream arduino-pico
pins_arduino.h (no NEOPIXEL/PIN_NEOPIXEL define). No chipGpios tag
applied.

NO ONBOARD USER PUSHBUTTON FOUND
----------------------------------
Confirmed absent by both the iLabs datasheet and product page (neither
mentions a discrete pushbutton beyond standard reset/BOOTSEL, which is
not a normal GPIO on RP2040, out of scope per the rpipico/board.json
precedent). No chipGpios tag applied.

CHIP-LEVEL/HEADER PINS -- NOT MODIFIED
-----------------------------------------
SPI0 (header pins, MISO=20/MOSI=23/SCK=22/SS=21), Wire0 (header pins,
SDA=0/SCL=1), and Serial1 (header pins, TX=16/RX=17) are routed to the
Feather header, not dedicated to any onboard peripheral -- left at
default full capabilities, consistent with every other Challenger
RP2040 sibling board audited in this session.

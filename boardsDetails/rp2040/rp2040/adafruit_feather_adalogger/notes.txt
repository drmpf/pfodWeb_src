SUMMARY
-------
Adafruit Feather RP2040 Adalogger (product 5743): Feather RP2040 with an
onboard microSD card slot for data logging (SPI1 bus, GPIO16/18-23), a
plain red status LED (GPIO13/D13), a single onboard status NeoPixel
(GPIO17), and a BOOT button also usable as a general input (GPIO7).
Created a new board.json with chipGpios entries for all 10 confirmed
dedicated/special-purpose GPIOs. Also fixed one bus-alias-contamination
bug in pins_arduino.h: removed the vendor-default `PIN_SPI0_SS (13u)`
alias (and its dependent `static const uint8_t SS = PIN_SPI0_SS;` line),
which directly collided with the confirmed onboard LED pin (GPIO13).

PER-PIN REASONING
------------------
GPIO7 (PIN_BUTTON / BOOT): digital_input + digital_output + pwm_output +
  button. Ordinary GPIO wired to a switch to GND, RP2040 internal
  pull-up enabled by software, active-low. Confirmed by Zephyr dts
  gpio_keys node + Adafruit's own pinouts guide. Full capability
  retained per this repo's established "ordinary GPIO button" precedent
  (adafruit_feather_scorpio GPIO7 is the identical pin/role).

GPIO13 (PIN_LED / D13): digital_output + pwm_output + led_high.
  Confirmed active-high onboard status LED via Zephyr dts leds node and
  Adafruit's own pinouts guide. digital_input dropped per this repo's
  established led_high precedent (rpipico, adafruit_feather_scorpio,
  adafruit_metro all drop digital_input on their confirmed LED pins).
  BUG FIX: this GPIO was also the vendor's default (unused) PIN_SPI0_SS
  alias in pins_arduino.h. Adafruit's own docs state there is no
  dedicated CS pin on the main SPI header (GPIO13 is just one of several
  arbitrary software-selectable SS choices) - so this alias was a false
  positive that would have contaminated the LED tag with a spurious
  spi_ss capability via build_boards.js's unconditional SS-alias
  auto-append. Removed `#define PIN_SPI0_SS (13u)` and the dependent
  `static const uint8_t SS = PIN_SPI0_SS;` line from pins_arduino.h
  (grepped the whole file afterward to confirm no other reference to
  either symbol remains). SPI1 (the SD card's own bus, PIN_SPI1_SS =
  PIN_SD_DAT3_CS = GPIO23) is a separate, untouched alias.

GPIO16 (PIN_CARD_DETECT): digital_input only. Mechanical card-presence
  switch on the microSD socket. digital_output/pwm_output dropped since
  driving this pin as an output could conflict with the socket's own
  switch state; digital_input retained since reading card presence is
  safe and useful. Matches this repo's solderparty_rp2350_stamp
  PIN_CARD_DETECT precedent exactly (same capability set/reasoning).

GPIO17 (PIN_NEOPIXEL): digital_output + led_neopixel. Confirmed single
  onboard WS2812 status NeoPixel (not a chain - Zephyr dts
  chain-length=1), active-high data line. digital_input not applicable
  (output-only data protocol pin), matching this repo's led_neopixel
  precedent (adafruit_feather_scorpio GPIO4, adafruit_metro GPIO14).

GPIO18/19/20/23 (PIN_SD_CLK/CMD_MOSI/DAT0_MISO/DAT3_CS = PIN_SPI1_SCK/
  MOSI/MISO/SS): capabilities suppressed to [] (empty). Dedicated
  microSD card connector SPI1 bus lines, vendor-confirmed via Adafruit's
  pinouts guide and CircuitPython mpconfigboard.h, not general-purpose.
  build_boards.js's unconditional SPI-role alias matching still attaches
  the correct spi_sck/spi_mosi/spi_miso/spi_ss tags on top from the
  PIN_SPI1_* aliases already present in pins_arduino.h - this is
  intentional and correct (reflects the pins' real SPI role), matching
  the sparkfun_thingplusrp2040 and solderparty_rp2350_stamp precedents.

GPIO21/22 (PIN_SD_DAT1/PIN_SD_DAT2): capabilities suppressed to [].
  Dedicated microSD 4-bit-SDIO data lines (unused by this core's default
  1-bit SPI-mode SD access, but still physically wired to/reserved by
  the card socket - not safe or meaningful general-purpose I/O). No
  SPI-role alias exists for these two GPIOs in pins_arduino.h, so no
  bus-role tag applies either, matching this repo's sparkfun_thingplusrp2040
  D10/D11 (DATA2/DATA1) precedent exactly.

NOT CHANGED / OUT OF SCOPE
---------------------------
- GPIO8/14/15 (general-purpose header SPI MISO/SCK/MOSI): left at
  chip-level default (full capability + auto-attached spi_miso/sck/mosi
  tags). Confirmed genuine header-broken-out pins via Adafruit's own
  "The main SPI1 SCK/MOSI/MISO" pinout labels, not dedicated to any
  onboard peripheral.
- GPIO2/3 (Wire0 SDA/SCL, STEMMA QT connector): left at chip-level
  default. Confirmed general-purpose I2C connector pins via Adafruit's
  own pinouts guide, consistent with every other audited Feather board's
  STEMMA QT treatment in this repo.
- GPIO0/1 (Serial1 TX/RX): ordinary UART pins, no override needed.
- GPIO26-29 (A0-A3): chip-level ADC default applies unchanged; no
  LED/button/NeoPixel/dedicated-hardware alias on these pins.
- RESET button: not GPIO-readable on this design (hardware reset only,
  same as every other RP2040 board's RESET line) - out of scope for GPIO
  capability tagging, consistent with every other RP2040 board audited
  in this repo.

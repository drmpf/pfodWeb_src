PER-PIN REASONING
------------------
GPIO25 (PIN_LED / LED_BUILTIN):
  - Declared in this board's pins_arduino.h as PIN_LED (25u), included via generic/common.h's
    `#ifdef PIN_LED / #define LED_BUILTIN PIN_LED`.
  - Confirmed onboard LED per uPesy's own quickstart guide (built-in blue LED, pre-flashed blink demo).
  - Confirmed active-high polarity: uPesy's own quickstart Blink example for this exact board uses
    digitalWrite(LED_BUILTIN, HIGH) to turn the LED on, matching the standard Arduino Blink idiom and
    the rpipico precedent (GPIO25, active-high, same physical Pico-style LED-anode-to-GPIO-via-resistor
    wiring assumption).
  - No SPI/Wire/SS/MOSI/MISO/SCK/SDA/SCL alias collision on GPIO25 (SPI0: MISO16/MOSI19/SCK18/SS17;
    SPI1: MISO12/MOSI15/SCK14/SS13; Wire0: SDA4/SCL5; Wire1: SDA22/SCL23) — no build_boards.js
    bus-capability-collision bug to fix on this board.
  - Tagged: ["digital_output", "pwm_output", "led_high"] — digital_input dropped per this repo's
    established led_high/led_low precedent for dedicated onboard LED pins (rpipico GPIO25,
    esp32/esp32c5/XIAO_ESP32C5 GPIO27, esp8266/esp8266/wiolink GPIO2). pwm_output kept since
    arduino-pico's analogWrite() works on any RP2040 GPIO (8 PWM slices cover GPIO0-29), enabling
    LED brightness dimming.

RESET button ("button to restart the card"):
  - uPesy's product page lists this as a board improvement over the stock Pico. This is a hardware
    RESET button (wired to the RP2040 RUN pin, pulling it low), not a GPIO-readable digitalRead()
    button — no numbered GPIO to attach a "button" capability to. Out of scope for this repo's
    GPIO-keyed capability tagging, consistent with how BOOTSEL is handled on every other RP2040
    board in this repo (see rpipico/board.json's note).
  - No additional user/BOOTSEL-equivalent GPIO button found in any consulted source.

NeoPixel: none found/documented — no onboard NeoPixel on this board per any consulted source.

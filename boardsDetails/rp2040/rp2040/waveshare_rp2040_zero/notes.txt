PER-PIN REASONING
- GPIO16 (PIN_NEOPIXEL): Onboard WS2812 addressable RGB LED, confirmed via three independent
  sources (Waveshare product page, teachmemicro.com, mischianti.org) plus TinyGo's board definition,
  all agreeing on GPIO16. This is the board's ONLY onboard visual indicator — confirmed there is no
  separate plain LED (teachmemicro.com is explicit on this point, consistent with the task's hint
  about Waveshare "Zero" form-factor boards). Tagged output-only:
  "capabilities": ["digital_output", "led_neopixel"] — matches the established
  vccgnd_yd_rp2040/board.json GPIO23 precedent (same rp2040 family, same PIN_NEOPIXEL alias pattern).
  pwm_output omitted per this repo's NeoPixel convention (WS2812 is a bit-serial protocol data line,
  not a PWM-dimmable output). digital_input dropped since the pin is write-only in normal use, same
  rationale as every other NeoPixel-tagged pin in this codebase.
- No PIN_LED alias exists anywhere in this board's pins_arduino.h — nothing to tag as led_high/led_low.
- BOOT button: standard RP2040 bootloader-entry button, out of scope per task instructions (same
  BOOTSEL rationale already established in rpipico/board.json — not a normal GPIO digitalRead(),
  and this board's pins_arduino.h declares no alias for it anyway).
- RESET button: hardware reset, not represented by any pins_arduino.h alias — no GPIO to tag.
- No other user-accessible buttons found in any consulted source.
- inputOnlyGpios / pinNotes / pwm / dac / adc all left at chip-level defaults (12-bit ADC, 8-bit
  analogWrite, no DAC) — this board's pins_arduino.h declares no board-specific analog aliases beyond
  ../generic_full/common.h.

PER-PIN REASONING
------------------
GPIO16 (PIN_NEOPIXEL, from pins_arduino.h line "#define PIN_NEOPIXEL (16u)"):
  - Confirmed as the board's sole onboard WS2812 addressable RGB LED (a single pixel, not a matrix —
    explicitly distinguished from the sibling RP2040-Matrix board).
  - pins_arduino.h leaves "//#define LED_BUILTIN PIN_NEOPIXEL" commented out, and no PIN_LED is defined
    anywhere in this board's header or its included generic_full/common.h — confirms there is genuinely
    no separate plain/standard LED on this board, consistent with the "Waveshare one-indicator" pattern
    already established on waveshare_rp2040_zero and waveshare_rp2040_matrix.
  - Tagged capabilities: ["digital_output", "led_neopixel"] — output-only (bypasses default
    input-derivation that would otherwise also add digital_input), no pwm_output (WS2812 is a
    bit-serial-protocol data line, not a PWM-dimmable pin), matching this repo's established
    NeoPixel-tagging convention.
  - Bus-collision check: this board's pins_arduino.h declares SPI0 (MISO=4, MOSI=3, SCK=2, SS=5),
    SPI1 (MISO=12, MOSI=15, SCK=14, SS=13), Wire0 (SDA=4, SCL=5), Wire1 (SDA=26, SCL=27), Serial1
    (TX=0, RX=1), Serial2 (TX=8, RX=9). GPIO16 does not appear in any of these — no collision, so no
    pins_arduino.h edit is needed to prevent build_boards.js from auto-appending a spurious bus
    capability to GPIO16.

Buttons: only BOOT and RESET exist on this board (confirmed via thepihut.com product page). BOOT enters
  ROM bootloader mode (not a normal GPIO digitalRead()) and RESET is a hardware reset line — neither has
  a pins_arduino.h alias, so both are out of scope for capability tagging (same rationale already
  documented in ../rpipico/board.json, ../waveshare_rp2040_zero/board.json, and
  ../waveshare_rp2040_matrix/board.json). No other onboard buttons are documented for this board.

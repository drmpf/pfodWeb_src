pfodWeb RP2040 family audit — board: ilabs_rpico32 (chip bucket: rp2040)
Audit date: 2026-07-13

BOARD IDENTITY
==============
iLabs "RPICO32" — a bare RP2040 + ESP8285 WiFi SOM/module (5.07 x 2.28 x
0.72 cm per iLabs' own product page), sold as a solderable module rather
than an assembled devkit. NOT the same product as the "Challenger RP2040
WiFi" (challenger_2040_wifi variant) which is a full Adafruit-Feather-form
-factor devkit from the same vendor with onboard LED/NeoPixel — RPICO32
is a smaller, bare module with no onboard user I/O beyond the ESP8285
WiFi link itself.

Architecture: RP2040 (dual-core Cortex-M0, 133MHz, 8MB QSPI flash, 264KB
SRAM, 12MHz crystal) as host processor, paired with an ESP8285 WiFi
(2.4GHz) co-processor with 1MB internal flash, connected over UART0
(GPIO0 TX / GPIO1 RX) at up to 1Mbit/s, plus two RP2040 GPIO control
lines (GPIO2 = active-low reset, GPIO3 = mode-select for flash mode
entry). This is the same "host + AT-style UART WiFi co-processor"
architecture family as challenger_2040_wifi (which uses an ESP8285 too,
just on different GPIOs/UART instance) — NOT the native RP2040 + CYW43439
combo used by Pico W / the "rp2040w" chip bucket.

PER-PIN REASONING (chipGpios entries written)
==============================================
GPIO0 (PIN_SERIAL1_TX / PIN_ESP_TXD) - dedicated ESP8285 co-processor
  UART0 TX line. capabilities: [].
GPIO1 (PIN_SERIAL1_RX / PIN_ESP_RXD) - dedicated ESP8285 co-processor
  UART0 RX line. capabilities: [].
GPIO2 (PIN_ESP_RESET) - ESP8285 active-low reset line, driven by RP2040.
  Confirmed active-low by vendor product page. capabilities: [].
GPIO3 (PIN_ESP_MODE) - ESP8285 flash-mode select line, driven by RP2040
  during firmware updates. Confirmed by vendor product page.
  capabilities: [].

Rationale for needing these overrides despite pins_arduino.h having no
"Dn" alias for GPIO0-3 any more: build_boards.js's numeric #define
fallback resolution still recognizes PIN_SERIAL1_TX / PIN_SERIAL1_RX /
PIN_ESP_RESET / PIN_ESP_MODE themselves as GPIO aliases, so absent a
chipGpios override these 4 pins would silently inherit full
digital_input/digital_output/pwm_output capability from the chip-level
empty chipGpios default — exactly the same mechanism already documented
for challenger_2040_wifi's GPIO4/5/13/19 overrides.

Bus-collision bug class (SDA/SCL/SS/MOSI/MISO/SCK auto-append) checked:
GPIO0-3 carry no SPI/I2C/other bus alias on this board — Wire0 is
SDA=GPIO4/SCL=GPIO5, SPI0 is MISO=24/MOSI=23/SCK=22/SS=21, Serial2 is
TX=8/RX=9, all disjoint from GPIO0-3 — so this bug class does not apply
here. No pins_arduino.h edit was made or needed.

LED / NEOPIXEL / BUTTON VERDICT
================================
NO onboard status LED, NO onboard NeoPixel/addressable RGB LED, and NO
onboard user pushbutton (beyond RP2040's own non-GPIO BOOTSEL) exist on
this board — confirmed via the vendor's own detailed product feature
list, which mentions crystal speed and flash chip speed but nothing
resembling an LED or button. This is a genuine NO CHANGE for
LED/NeoPixel/button tagging on this board — not a missed tag. No
"led_high"/"led_low"/"led_neopixel"/"button" capability was added
anywhere in this board's chipGpios.

SUMMARY (one line)
===================
ilabs_rpico32 (bare RP2040+ESP8285 WiFi module, no onboard LED/NeoPixel/
button): created board.json with chipGpios overrides zeroing out
GPIO0/1/2/3 (dedicated ESP8285 UART0 TX/RX + reset + mode-select lines)
to prevent them inheriting full digital I/O capability from the empty
chip-level default; no bus-collision bug found; no LED/NeoPixel/button
tags applicable (none exist on this bare module per vendor documentation).

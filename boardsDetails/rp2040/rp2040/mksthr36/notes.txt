MKS THR36 (chip: rp2040) — dedicated-hardware pin-exclusion audit
==================================================================
Date: 2026-07-13
Board dir: variants\rp2040\rp2040\mksthr36\
Result: board.json CREATED with 11 chipGpios overrides (real defects fixed).

SUMMARY (one line)
-------------------
MKS THR36 is a real Makerbase RP2040 3D-printer CAN/USB toolhead expansion
module (TMC2209 E-axis driver, ADXL345 accelerometer, BLTouch, X/Y endstops,
filament sensor, 3 fans, heater, NeoPixel); 11 GPIOs that pins_arduino.h
exposed as plain general-purpose D-number/A-number aliases were actually
committed to this onboard/connector hardware and are now excluded (or, for
the NeoPixel, retagged led_neopixel) via chipGpios overrides; 6 GPIOs
(SPI0 bus GPIO16-19, Wire0/I2C bus GPIO22-23) have no vendor-confirmed
onboard consumer and were deliberately left general-purpose (KEEP, not a
guess) pending better documentation.

SOURCES CONSULTED
------------------
1. https://github.com/makerbase-mks/MKS-THR36-THR42-UTC
   Official vendor repo. README.md feature list: "integrates a TMC2209
   driver (for E-axis) and an ADXL345 sensor... supports interfaces for
   BLtouch, neopixel, three controllable fans, and X, Y, Z endstops...
   integrated CAN transceiver with a 120-ohm terminal resistance... BOOT
   button can be used for RP2040 to update the firmware on USB mode."
   THR36 = NEMA14 stepper variant, THR42 = NEMA17 variant, same PCB/pinout
   family (both share byte-identical pins_arduino.h in this repo, and the
   sibling mksthr42 board is not yet audited/has no board.json).

2. https://github.com/makerbase-mks/MKS-THR36-THR42-UTC/blob/main/MKS_THR.cfg
   Vendor-provided Klipper reference config — the single most authoritative
   source for this audit since it maps functional names directly to GPIO
   numbers (Klipper "MKS_THR:gpioNN" pin syntax). Confirmed assignments:
     gpio0  = heater_pin (E0 heater)
     gpio1  = hotend fan
     gpio2  = generic fan0
     gpio3  = generic fan1
     gpio4  = dir_pin (E0)
     gpio5  = step_pin (E0)
     gpio6  = TMC2208/2209 uart_pin (E0 driver, single-wire UART)
     gpio10 = enable_pin (E0)
     gpio12 = ADXL345 MISO
     gpio13 = ADXL345 CS (chip select)
     gpio14 = ADXL345 SCK
     gpio15 = ADXL345 MOSI
     gpio24 = endstop_pin (stepper_x section)
     gpio25 = endstop_pin (stepper_y section)
     gpio26 = sensor_pin (E0 thermistor ADC)
     gpio20 = neopixel data pin (commented-out block)
     gpio21 = probe/BLTouch sensor_pin (commented-out block)
     gpio11 = BLTouch control/servo pin (commented-out block)
   Fetched both via the GitHub blob view and the raw.githubusercontent.com
   URL; both returned consistent pin assignments.

3. Community Klipper configs / Klipper Discourse threads referencing this
   exact board, confirming:
     `[filament_switch_sensor sp_sensor_runout] switch_pin: ^MKS_THR:gpio29`
   i.e. GPIO29 is the board's filament-runout sensor input connector.

4. https://makerbase3d.com/product/mks-thr36-thr42-board/
   Vendor product listing — independent confirmation of TMC2209, ADXL345,
   CAN (Canable/Canbus), and PT1000 thermistor support, 3-fan + 1-heater
   output count (matches gpio0-3 mapping above).

5. https://canbus.esoterical.online/toolhead_flashing/common_hardware/MKS%20THR36%20V1.0/README.html
   Independent community CANBus flashing guide for this exact board -
   confirms board identity/BOOTSEL flashing procedure and 120R CAN
   terminator jumper, but has no GPIO pinout table of its own (defers to
   the vendor MKS_THR.cfg above).

6. variants\rp2040\rp2040\mksthr36\pins_arduino.h (this repo) - read in
   full. Already carries a "pfodWeb NOTE" comment (identical, byte-for-
   byte, in the sibling mksthr42\pins_arduino.h) stating GPIO0,1,2,3,4,5,
   6,8,9,10 are dedicated and given no static-const alias at all - this
   was evidently added in an earlier pass of this same ongoing family
   audit and independently matches this session's own analysis of which
   GPIOs the ESP32-style parser (parseEsp32Consts, static-const-only) can
   even see. This audit's job was the remaining GPIOs that DO carry an
   alias but are nonetheless dedicated.

7. variants\rp2040\rp2040\board.json (chip-level defaults, chipGpios: {})
   and variants\rp2040\rp2040\bigtreetech_SKR_Pico\board.json (real
   3D-printer-mainboard precedent) - both read in full before writing
   this board's file; bigtreetech_SKR_Pico's endstop/probe/filament-
   sensor-as-capabilities:[] and NeoPixel-as-led_neopixel treatment was
   used as the direct template for equivalent MKS THR36 pins.

LED / BUTTON
-------------
No onboard user LED beyond the NeoPixel (GPIO20/PIN_NEOPIXEL, tagged
led_neopixel above). No onboard general-purpose user button is documented;
the only physical button mentioned anywhere (vendor README) is the
RP2040's own BOOTSEL button used to enter UF2 firmware-update mode, which
per the rpipico/board.json precedent is not a normal GPIO and is out of
scope for this repo's GPIO-keyed capability tagging.

BUS/BUTTON-LED COLLISION BUG CHECK
------------------------------------
Checked whether any confirmed button/LED pin is also aliased as SDA/SCL/
SS/MOSI/MISO/SCK (the recurring bug class from this session's earlier
boards). Result: no collision found. The only LED (NeoPixel, GPIO20) has
no bus alias at all. The dedicated SPI1 pins (12-15, ADXL345) are plain
D-number aliases, not the generic Arduino SS/MOSI/MISO/SCK names (those
generic names live on the separate, untouched SPI0 pins 16-19). No
#define removal or dangling-reference cleanup was needed in
pins_arduino.h for this board.

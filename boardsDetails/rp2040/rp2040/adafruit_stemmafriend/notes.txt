WHAT THIS BOARD IS
The "STEMMA Friend" is a small handheld I2C/UART diagnostic "multi-tool"
built by Adafruit: a 240x240 pixel IPS TFT display dominates its front
face, it has two STEMMA QT connectors (I2C bus 0) plus one Grove/JST
connector (I2C bus 1, switchable to UART with auto-baud detection), a JST
battery connector, and a single physical pushbutton. The original hardware
(covered in Adafruit's own blog in Oct 2020) was SAMD21E-based; the
"adafruit_stemmafriend" variant audited here is an RP2040 hardware
revision that ships as an officially supported board definition in
earlephilhower/arduino-pico.

It appears to be an Adafruit-internal / limited-release engineering tool
rather than a mainstream retail product: no dedicated learn.adafruit.com
guide, no adafruit.com product page, and no pinout/schematic diagram page
could be located for it despite multiple targeted searches. It also has no
CircuitPython port (ports/raspberrypi/boards/adafruit_stemmafriend returns
404 on GitHub), consistent with it being a fixed-firmware diagnostic tool
rather than a general-purpose CircuitPython dev board.

PER-PIN REASONING

GPIO11 (PIN_SWITCH, aliased as D11):
  CONFIRMED genuine physical pushbutton -- the macro name itself (source 1)
  states "switch", and source 2 describes a handheld tool with an
  integrated screen and no other described input, consistent with this
  being the tool's primary UI button. Tagged with full capability
  (digital_input, digital_output, pwm_output, button), matching this
  repo's adafruit_qtpy GPIO21 / adafruit_itsybitsy GPIO13 precedent for an
  ordinary GPIO wired to a mechanical switch (not a dedicated silicon
  trick like the plain Pico's BOOTSEL-via-QSPI-CS mechanism). Checked
  against every bus alias on this board (SPI0 MOSI=7/MISO=4/SCK=2/SS=1,
  WIRE0 SDA=20/SCL=21, WIRE1 SDA=26/SCL=27, Serial1 TX=26/RX=27, Serial2
  TX=20/RX=21) -- GPIO11 collides with none of them, so no
  pins_arduino.h edit was needed.

GPIO12 (PIN_LED, aliased as D12):
  CONFIRMED to be the TFT backlight control line, NOT a general-purpose
  status LED -- this board's own pins_arduino.h author comment
  ("backlight, weird but why not?") plus source 2's description of an
  integrated 240x240 TFT dominating the board face together rule out a
  plain indicator-LED interpretation. digital_input dropped (dedicated
  backlight-control output, matching this repo's led_high/led_low
  precedent for dedicated onboard LED pins -- e.g. rpipico GPIO25).
  pwm_output kept (arduino-pico's analogWrite() works on any RP2040 GPIO
  per this chip family's own pwm note, and PWM-dimmed backlights are
  standard on small TFT panels). Tagged led_high on the same idiom-based
  reasoning this repo already applies to every other arduino-pico
  PIN_LED/LED_BUILTIN pin (the uniform digitalWrite(LED_BUILTIN, HIGH) //
  LED on convention used throughout arduino-pico's bundled examples).
  CAVEAT: unlike the rpipico GPIO25 precedent (backed by an official
  Raspberry Pi datasheet), this specific pin's active polarity is NOT
  independently vendor-confirmed -- no learn.adafruit.com pinout page or
  schematic for this board could be located. This is flagged here for
  visibility; if a future session locates an authoritative schematic for
  this board that contradicts active-high, the led_high tag should be
  corrected to led_low at that time.

GPIO17 (PIN_NEOPIXEL, aliased as D17):
  CONFIRMED single onboard status NeoPixel (WS2812), output-only data
  line -- NUM_NEOPIXEL=1 in this board's own pins_arduino.h, and no
  NEOPIXEL_POWER macro appears anywhere in the file (unlike adafruit_qtpy,
  which has a separate GPIO11 power-gate pin -- this board's GPIO11 is
  instead the PIN_SWITCH button, a different pin entirely). Tagged
  ["digital_output","led_neopixel"], matching this repo's adafruit_qtpy
  GPIO12 / adafruit_itsybitsy GPIO17 precedent (no digital_input/
  pwm_output -- NeoPixel protocol timing is driven via the RP2040 PIO
  peripheral, not analogWrite/digitalRead). Checked against every bus
  alias on this board -- no collision, no pins_arduino.h edit needed.

GPIO1 / GPIO2 / GPIO4 / GPIO7 (SPI0 TFT SS/SCK/MISO/MOSI):
  Already excluded from this board's own D-pin alias list by a
  pre-existing pfodWeb NOTE at the top of pins_arduino.h (added in an
  earlier session, before this audit). No chipGpios entry needed or
  possible -- under the RP2040 family's "empty chip-level chipGpios"
  mechanism, a GPIO with no alias at all in pins_arduino.h simply does not
  surface as a pin in the Designer.

BUG-CLASS CHECK (button/LED pin also aliased as a bus pin, silently
getting an auto-appended bus capability from build_boards.js): checked
all three tagged GPIOs (11, 12, 17) against every SDA/SCL/SS/MOSI/MISO/SCK
alias declared in this board's pins_arduino.h -- no collisions found. No
pins_arduino.h edit was required for this board.

RP2040 family audit — board: DudesCab
Date: 2026-07-13
Chip: rp2040 (variants/rp2040/rp2040/DudesCab/)

BOARD IDENTITY
--------------
boards.txt entry: `DudesCab.name=L'atelier d'Arnoz DudesCab`
This is the commercial "Dude's Cab" board — a virtual-pinball-cabinet I/O
controller made by the French maker/shop "L'atelier d'Arnoz". NOT a
sim-racing/cockpit controller despite the "Cab" name superficially
suggesting one; "Cab" here means pinball cabinet. Built around an
overclocked RP2040 (boards.txt shows freq menu options up to 300 MHz
overclock, f_cpu default 125000000).

SOURCES CONSULTED
-----------------
1. Vendor product page:
   https://shop.arnoz.com/en/dude-s-cab/131-dude-s-cab-v1.html
   - "Board based on an overclocked Raspberry RP2040 microcontroller"
   - USB-C interface
   - 32 button inputs, 5 of them "ultra-low latency" (flipper/magna/fire
     buttons: 0.73ms latency; others 1.62ms)
   - 6-pin plunger input, with 2 configurable virtual buttons on the plunger
   - Built-in accelerometer (configurable dead zones, virtual TILT button)
   - Up to 128 DOF (Direct Output Framework) outputs via a daisy-chained
     expansion-board system (each expansion card adds 16 PWM/MOSFET outputs)
   - Fully compatible with DOF and DOFLINX
   - MX LED support via an "MX DONNY" adapter (button-cap LED lighting)
   - Configuration via a dedicated PC "Dude's Cab Configurator" app over USB

2. Official English user guide PDF:
   https://dude.arnoz.com/dude_Cab_English_guide.pdf
   - Fetched and scanned for GPIO/pinout/schematic content — none found.
     Document is user/software-configuration focused (Configurator app
     usage, firmware update via DFU/UF2), not a hardware pinout reference.

3. ManualsLib-hosted copy of the user manual:
   https://www.manualslib.com/manual/3467873/L-Atelier-D-Arnoz-Dude-S-Cab.html
   - Same conclusion: mentions button port labels ("BTLA et BTLB", "DPAD"),
     JST-PH connectors, terminal screws, but no RP2040 GPIO-level mapping.

4. WebSearch for a public firmware/schematic repo (e.g. "arnoz dudes-cab
   github", "pins.h") — no GitHub repository or schematic found.

5. This board's own pins_arduino.h (variants/rp2040/rp2040/DudesCab/
   pins_arduino.h) — hand-edited (not a bare passthrough include), but
   its header comment ("Pin definitions taken from: datasheets.
   raspberrypi.org/pico/pico-datasheet.pdf") is identical boilerplate to
   the reference Pico's own pins_arduino.h, i.e. it looks like it started
   from the stock Pico template. Declares only:
     PIN_LED (25u)
     Serial1 (GPIO0/1), Serial2 (GPIO8/9)
     SPI0 (MISO4/MOSI3/SCK2/SS5), SPI1 (MISO12/MOSI15/SCK14/SS13)
     Wire0 (SDA18/SCL19), Wire1 (SDA10/SCL11)
   then falls through to ../generic/common.h for D0-D22/A0-A2 (GPIO26-28).
   No button-matrix, accelerometer-interrupt, or DOF-driver pin aliases are
   declared anywhere in this file — consistent with those functions being
   reached through onboard I/O-expander/driver hardware (I2C/SPI or a
   dedicated multiplexing scheme) rather than raw per-function GPIO
   aliases, matching the vendor's 32-button/128-output I/O count that
   exceeds RP2040's ~26 usable GPIOs by a wide margin.

PER-PIN REASONING
------------------
GPIO25 (PIN_LED / LED_BUILTIN):
  On the plain reference Pico (rpipico/board.json) and the WIZnet
  W5500-EVB-Pico (wiznet_5500_evb_pico/board.json), GPIO25 is confirmed
  active-high onboard-LED via explicit vendor documentation ("LED is
  connected to GP25" / "GPIO25 Connected to user LED"). No equivalent
  statement exists for the Dude's Cab in any source found above — it is
  a fully custom third-party PCB (not a Pico-form-factor clone), and its
  pins_arduino.h header comment suggests PIN_LED=25 may be an inherited
  template default rather than a value re-verified against this specific
  board's actual schematic. Left UNTAGGED (no chipGpios override) rather
  than guessing polarity/role.

GPIO0-22, A0-A2 (26-28), SPI0/SPI1, Wire0/Wire1 bus pins:
  No vendor documentation ties any specific GPIO to a button, the
  accelerometer, plunger input, or DOF output. No override applied.

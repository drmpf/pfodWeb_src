PER-PIN REASONING
------------------
GPIO25 (PIN_LED):
  - Board's only onboard visual indicator per GeeekPi's own product description ("on-board LED is
    connected to GP25"), matching this board's pins_arduino.h PIN_LED (25u) definition.
  - Polarity: no GeeekPi-specific schematic or independently maintained device-tree (Zephyr does not carry
    a GeeekPi board) could be located to directly confirm active-high vs active-low. Tagged ACTIVE HIGH
    (led_high) on the strength of the unanimous convention observed across every other GPIO25-onboard-LED
    board already audited in this repo's RP2040 family: official Raspberry Pi Pico (../rpipico/board.json,
    datasheet-confirmed) and Waveshare's "RP2040 Plus" (../waveshare_rp2040_plus/board.json,
    Zephyr-dts-confirmed GPIO_ACTIVE_HIGH) - both physically near-identical Pico-pinout-compatible clones
    using the same GPIO25 pin for the same purpose. No led_low precedent exists anywhere in this repo for
    a Pico-clone's dedicated GPIO25 LED. Flagged as inferred-not-schematic-confirmed in the board.json note
    for transparency.
  - Applied capabilities: ["digital_output", "pwm_output", "led_high"] - digital_input dropped (matches
    established led_high precedent for dedicated onboard LED pins, e.g. ../rpipico/board.json GPIO25,
    ../waveshare_rp2040_plus/board.json GPIO25). pwm_output retained since arduino-pico's analogWrite()
    works on any RP2040 GPIO (all 8 PWM slices cover GPIO0-29), enabling LED brightness dimming.

BOOT / RESET buttons:
  - Both out of scope for capability tagging: confirmed present via GeeekPi's product description ("reset
    button", "boot selection button") but neither is represented by any alias in pins_arduino.h and neither
    is readable via a normal GPIO digitalRead() - RESET pulls the RUN net low in hardware, BOOTSEL is
    sampled via the RP2040 ROM's special QSPI-CS-line trick (same rationale already established in
    ../rpipico/board.json and ../waveshare_rp2040_plus/board.json). No chipGpios entry needed/possible for
    either.

NeoPixel: none mentioned in any GeeekPi product listing or in this board's pins_arduino.h/common.h - no
tag applied.

Bus-collision check (per the audit's known bug class): GPIO25 carries no SDA/SCL/SS/MOSI/MISO/SCK alias in
this board's pins_arduino.h (SPI0 = GPIO16-19, SPI1 = GPIO12-15, Wire0 = GPIO4/5, Wire1 = GPIO26/27) - no
collision, no pins_arduino.h edit needed.

Board: SparkFun "Pro Micro RP2040" (chip bucket: rp2040)
Directory: variants/rp2040/rp2040/sparkfun_promicrorp2040/
Audit date: 2026-07-12

SUMMARY
-------
Applied NeoPixel tagging to GPIO25 (the board's single onboard WS2812
addressable RGB LED, which doubles as the status LED). No button tagging
applied - the board's only buttons (BOOT/RESET) are hardware-only and not
wired to a normal GPIO. Created board.json (this board previously had
none - zero differentiation from the chip-level empty-chipGpios default,
meaning the Designer would have offered GPIO25 as a plain digital_output/
digital_input/pwm_output pin with no indication it's actually a single
addressable pixel).

SOURCES CONSULTED
------------------
1. SparkFun's own official Pro Micro RP2040 Hookup Guide
   (learn.sparkfun.com/tutorials/pro-micro-rp2040-hookup-guide/all) -
   authoritative. States verbatim: "There are two LEDs on the Pro Micro
   RP2040. The red LED indicates whether power is present. The other is
   the addressable WS2812 RGB LED... The addressable LED is connected to
   GPIO25. You'll [need] to define functions or use the WS2812 library to
   control that LED. There is a pad on the back of the board that is
   connected to the WS2812's DO pin. If you decide to daisy chain more
   LEDs, you'll want to solder to this pad."
   Also confirms BOOT and RESET buttons are hardware-only, not
   GPIO-connected: "Boot Button: Forces USB mass storage mode by
   connecting to the external flash memory" / "Reset Button: Restarts the
   RP2040 microcontroller" - neither is a numbered GPIO pin.
2. WebSearch cross-reference: community.sparkfun.com/t/pro-micro-rp2040-
   controlling-ws2812/42583 (SparkFun's own community forum) independently

   (NUM_NEOPIXEL=1 matches).

   one addressable WS2812 LED doing double duty as the status LED (the

PER-PIN REASONING
------------------
GPIO25 (PIN_LED / PIN_NEOPIXEL, single onboard WS2812 pixel): tagged
  ["digital_output", "led_neopixel", "pwm_output"].
  - "led_neopixel" (not "led_high"/"led_low"): this is one addressable
    WS2812 RGB pixel controlled via a serial bit-banged/PIO protocol, not
    a simple two-state on/off LED - confirmed by NUM_NEOPIXEL=1 and the
    Hookup Guide's explicit "WS2812 library" instruction.
  - "digital_output" kept, "digital_input" dropped: the pin is
    permanently committed to driving the NeoPixel data line; it has no
    legitimate general-purpose input role.
  - "pwm_output" kept: matches the sparkfun_thingplusrp2350 GPIO14
    precedent exactly - arduino-pico's analogWrite() is available on any
    RP2040 GPIO, and keeping this capability does not conflict with the
    NeoPixel's actual bit-banged data protocol (the pin is not literally
    used for PWM dimming, but the capability tag itself is precedented
    for this exact board pattern and does not mislead the Designer into
    thinking it is a real hardware PWM peripheral rather than the
    bit-banged NeoPixel path - it is provided for tagging consistency
    with the sibling SparkFun board only).

No onboard user button - confirmed absent by the Hookup Guide (BOOT and
  RESET are both hardware-only, not GPIO-connected, same as every other
  RP2040 board's BOOTSEL). No button tagging applied.

Red power-indicator LED - NOT GPIO-connected (passive power indicator
  only, per the Hookup Guide), so out of scope for GPIO capability
  tagging entirely - there is no pin to attach a tag to.

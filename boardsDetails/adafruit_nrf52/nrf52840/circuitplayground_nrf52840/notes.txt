SOURCES CONSULTED
=================
1. This repo's own Adafruit_nrf52/variants/circuitplayground_nrf52840/
   variant.h — PRIMARY source for pin numbers.
2. https://raw.githubusercontent.com/adafruit/Adafruit_CircuitPlayground/master/Adafruit_Circuit_Playground.h
   (downloaded directly via curl and inspected, not summarized) —
   AUTHORITATIVE source for which pin is which onboard component. Same
   method already established and documented for this repo's AVR
   "Circuit Playground Classic" board (variants/arduino/avr/
   circuitplay32u4/board.json) — this library hard-codes the exact pin
   number of every onboard component per chip family via #ifdef/#elif
   blocks, and is more reliable than a generic pinout guide since it's
   literally the code the reference examples run.
   The `#elif defined(ARDUINO_NRF52840_CIRCUITPLAY)` block (this exact
   board) declares:
     CPLAY_LEFTBUTTON=4, CPLAY_RIGHTBUTTON=5, CPLAY_SLIDESWITCHPIN=7,
     CPLAY_NEOPIXELPIN=8, CPLAY_REDLED=13, CPLAY_BUZZER=A0,
     CPLAY_LIGHTSENSOR=A8, CPLAY_THERMISTORPIN=A9, CPLAY_LIS3DH_CS=-1,
     CPLAY_LIS3DH_INTERRUPT=27, CPLAY_LIS3DH_ADDRESS=0x19,
     CPLAY_CAPSENSE_SHARED=255 ("we use ground instead of capacitive
     sense pin").
   CPLAY_LIS3DH_CS=-1 confirms the onboard LIS3DH accelerometer is
   wired over I2C on this chip family (unlike the AVR 'classic' board,
   which uses a dedicated hardware SPI bus for the same chip) — matches
   this board's own variant.h declaring a second Wire interface
   (PIN_WIRE1_SDA=28/PIN_WIRE1_SCL=26, WIRE_INTERFACES_COUNT=2) for it.
   Neither Wire1 pin is aliased via bare static-const SDA1/SCL1, so
   they're already invisible by default — no action needed.

DECISIONS
=========
TAGGED: GPIO13 (PIN_LED1/CPLAY_REDLED) led_high, GPIO8 (PIN_NEOPIXEL)
led_neopixel, GPIO4 (PIN_BUTTON1/CPLAY_LEFTBUTTON) button, GPIO5
(PIN_BUTTON2/CPLAY_RIGHTBUTTON) button.

EXCLUDED (capabilities: [], each confirmed via the library source
above): GPIO14 (A0, buzzer — note: this file also declares a separate,
apparently-unused `PIN_BUZZER(12)` macro; the operative pin per the
actual library code is A0/GPIO14, not 12), GPIO22 (A8, light sensor),
GPIO23 (A9, thermistor).

PARTIALLY OVERRIDDEN: GPIO21 (A7) — vendor's own variant.h comment says
"not really analog!" and the library doesn't claim it for anything
specific, so it's kept as a real digital alligator-pad GPIO (this board
has 7 physical alligator clip pads labeled A1-A7) but WITHOUT the
analog_input capability, since the vendor itself says the ADC function
doesn't really work here.

NOT EXPOSED (invisible, #define-only): PIN_BUZZER(12) itself (separate
from the A0 alias that's actually used), PDM mic (GPIO24/25), the
LIS3DH's dedicated Wire1 I2C bus (GPIO26/28) and interrupt line
(GPIO27), QSPI flash (GPIO29-34), CPLAY_SLIDESWITCHPIN (GPIO7 — no
dedicated capability tag exists in this repo's vocabulary for a slide
switch, matching the DotStar precedent of not forcing a tag where none
fits).

KEPT available: A1-A6 (GPIO6,9,10,3,2,0) as general alligator pads
(A4/A5 also double as the default SPI bus MOSI/SCK, A6 also doubles as
the optional Serial1 RX — neither forces anything since neither is
force-aliased).

SECOND RE-CHECK (2026-09-13, same day, user re-requested the same
recheck — this time went past the Pinouts page's TEXT and downloaded
+ viewed the actual full pinout DIAGRAM IMAGE directly
(cdn-learn.adafruit.com/.../Adafruit_Circuit_Playground_Bluefruit_pinout.png),
per the method established in this session's Seeed XIAO nRF52840 work
(section 12 of [[newChipFamilyAI-guide]]). The diagram labels the
speaker "AUDIO" at index "12" and ALSO shows a previously-unknown
"SPEAKER_ENABLE" at index "11" — and separately labels "BUTTON_B" at
index "15", apparently contradicting this board's own PIN_BUTTON2=(5).

Per the user's explicit instruction this pass ("ignore CircuitPython as
that code path is not used" — the diagram's index numbers mix Arduino
and CircuitPython pin-naming conventions in ways not immediately
obvious from the image alone), resolved all of this against the ONE
source that actually matters for pfodWeb (the Arduino-side
variant.cpp), not the diagram's own numbering:

  const uint32_t g_ADigitalPinMap[] = {
    ...
     47,  // D5  is P1.15 (GPIO D5 / Right button)
    ...
     36,  // D11 is P1.04 (GPIO D11 / Speaker Shutdown)
     26,  // D12 is P0.26 (GPIO D12 / Audio Out)
    ...
     26,  // NOT REALLY ANALOG, A PLACEHOLDER SINCE D12 is not analog  <- this is index 14 (A0)
    ...
      6,  // D36(sic, actually index 35) is P0.06 (NeoPixel / Sensor switch)
  }

This CONFIRMS PIN_BUTTON2=(5) was correct all along — Arduino D5 really
does map to physical P1.15, matching the diagram's "P1.15" callout; the
diagram's "15" index label is a different (CircuitPython/physical-pin)
numbering scheme entirely, irrelevant to this repo's Arduino-only
parsing. NOT a bug, no fix needed.

It ALSO CORRECTED the earlier (first re-check's) resolution of the
audio-pin question: variant.cpp's own comment for index 14 literally
says "NOT REALLY ANALOG, A PLACEHOLDER SINCE D12 is not analog" —
meaning A0/GPIO14 is a placeholder ALIAS of D12/GPIO12 ("Audio Out"),
not a "same pad, different name" situation as the earlier WebSearch-
based resolution guessed. The GPIO14 exclusion decision doesn't change
(same physical pin either way), but board.json's note text was
corrected to cite this authoritative, primary variant.cpp comment
instead of the WebSearch-derived "A0 (also known as D12)" framing.

Also confirmed real, previously undocumented Arduino-side pins: D11
"Speaker Shutdown" (GPIO11) and, per the array's final entry, GPIO35
"NeoPixel / Sensor switch" (matching the diagram's "POWER_SWITCH").
Neither is aliased via `static const uint8_t` in variant.h (confirmed
via grep), so both are ALREADY invisible by default — no chipGpios
entry was needed for either, this is a documentation-completeness
addition only, not a capability change.

NOT GUESSED: every decision traces directly to the authoritative
Adafruit_CircuitPlayground library source, Adafruit's own Pinouts page,
the full pinout diagram image, AND (deciding fact, per the user's
explicit steer) this board's own Arduino-side variant.cpp — matching
the AVR sibling board's own established research method.

SUMMARY: 36 total Arduino pin indices (0-35); 4 tagged (1 LED, 1
NeoPixel, 2 button); 3 excluded (buzzer, light sensor, thermistor); 1
partially restricted (A7, digital-only); remainder (A1-A6/SPI/Wire0)
kept general-purpose; mic/Wire1/QSPI/slide-switch never appear
(unaliased #define-only, or no fitting vocabulary tag).

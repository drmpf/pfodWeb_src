SOURCES CONSULTED
=================
1. This repo's own Adafruit_nrf52/variants/pca10056/variant.h — PRIMARY
   source. 4 LEDs, 4 buttons, dual-UART setup (Arduino-header D0/D1 plus
   a separate J-Link-CDC virtual COM port, both optional/secondary since
   this chip has native USB).
2. LED polarity (LED_STATE_ON=0, active-low) trusted directly — this is
   the well-known, standard Nordic DK LED wiring convention (all Nordic
   reference dev kits, including the nRF52832/nRF52833/nRF5340 DKs,
   wire their 4 LEDs active-low), not independently re-verified via a
   fresh web search this pass.

PARSER-LEVEL FINDING — REQUIRED A SOURCE EDIT
==============================================
Same hex-sentinel bug as itsybitsy_nrf52840_express (see that board's
notes.txt for the full mechanism write-up): this board's variant.h
declares BOTH `PIN_A6` and `PIN_A7` as `(0xff)`, each aliased via a bare
`static const uint8_t A6/A7 = ...` line. build_boards.js's regex
misreads "0xff" as decimal "0" for both, which would have created a
phantom "A6/A7 (GPIO0)" pin (both colliding on the same wrong number).
FIX: deleted both alias lines outright from this repo's copy.

DECISIONS
=========
TAGGED: GPIO13-16 (PIN_LED1-4) led_low. GPIO11/12/24/25 (PIN_BUTTON1-4)
button.

KEPT available: A0-A5 (GPIO3,4,28-31), AREF (GPIO2), Serial1 (Arduino
header D0/D1, GPIO33/34), Serial2 (J-Link CDC, GPIO6/8), SPI bus
(GPIO44-47), Wire bus (GPIO26/27) — none have a confirmed dedicated
onboard consumer; this is a bare reference dev kit with a full
breakout header, not a product with fixed onboard sensors.

NOT EXPOSED: QSPI flash (GPIO17,19-23), NFC1/NFC2 (GPIO9/10) —
#define-only.

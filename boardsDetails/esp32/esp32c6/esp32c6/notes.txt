Audit date: 2026-07-12

pins_arduino.h summary (read in full):
  PIN_RGB_LED 8, LED_BUILTIN/RGB_BUILTIN wired to it, RGB_BRIGHTNESS 64
  TX=16, RX=17, SDA=23, SCL=22, SS=18, MOSI=19, MISO=20, SCK=21
  A0..A6 = GPIO0..GPIO6
  WIRE1_PIN_DEFINED, SDA1=6, SCL1=7 ("LP I2C Pins are fixed on ESP32-C6")

Sources consulted:
  1. https://docs.espressif.com/projects/esp-dev-kits/en/latest/esp32c6/esp32-c6-devkitc-1/user_guide.html
     Official Espressif esp-dev-kits documentation for ESP32-C6-DevKitC-1.
     States the board has an addressable RGB LED "driven by GPIO8" and
     lists GPIO8 as one of the chip's strapping pins (MTMS, MTDI, GPIO8,
     GPIO9, GPIO15). Same page's pin-function table gives:
       GPIO6 = MTCK, GPIO6, LP_GPIO6, LP_I2C_SDA, ADC1_CH6, FSPICLK
       GPIO7 = MTDO, GPIO7, LP_GPIO7, LP_I2C_SCL, FSPID
     Neither pin's function list references any onboard peripheral beyond
     the fixed LP_I2C controller pin mux.
  2. ESP32-C6 Series Datasheet (espressif.com) - confirms LP_GPIO6/
     LP_GPIO7 are the chip's fixed low-power I2C controller pins,
     matching this variant's own pins_arduino.h comment.
  3. General web corroboration (esp32.co.uk pinout guide, espboards.dev,
     mischianti.org) - all independently confirm a WS2812 addressable
     RGB LED wired to GPIO8 on the ESP32-C6-DevKitC-1, consistent with
     Espressif's own documentation.

Reasoning:
  GPIO8 (PIN_RGB_LED): CONFIRMED real onboard WS2812 NeoPixel, stated by
  Espressif's own official user guide for the exact physical reference
  board this generic entry models. High confidence - primary vendor
  source, well-documented mainstream product, plus independent
  third-party corroboration. Tagged capabilities
  ["digital_output","led_neopixel","pwm_output"], matching this repo's
  existing led_neopixel precedent (waveshare_esp32_s3_zero GPIO21,
  adafruit_qtpy_esp32c3 GPIO2).

  Alias-collision check (new step this session): compared GPIO8 against
  this variant's own TX/RX/SDA/SCL/SS/MOSI/MISO/SCK alias list
  (16/17/23/22/18/19/20/21) - GPIO8 is not aliased as any of those, so
  no conflicting boilerplate bus alias exists for this pin. No
  pins_arduino.h edit was needed.

  GPIO6/GPIO7 (SDA1/SCL1, second/LP I2C bus): KEEP as general-purpose
  I2C. Espressif's own pin-function table shows these are just the
  chip's fixed LP_I2C controller pins (a hardware pin-mux constraint,
  not evidence of an onboard I2C device) with no documented onboard
  peripheral consumer on the DevKitC-1 reference board. Left unchanged
  from chip-level board.json defaults (GPIO6: analog_input+digital_input
  +digital_output+pwm_output; GPIO7: digital_input+digital_output+
  pwm_output).

Summary: Created variants/esp32/esp32c6/esp32c6/board.json (full copy of
the chip-level esp32c6/board.json default) with GPIO8 retagged
["digital_output","led_neopixel","pwm_output"] for the confirmed onboard
WS2812 RGB LED; GPIO6/GPIO7 left as general-purpose I2C (no change); no
alias-collision bug found on this board.

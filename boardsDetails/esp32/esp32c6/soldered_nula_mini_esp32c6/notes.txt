Reasoning:
  The authoritative signal here is the merged upstream PR: this repo's
  pins_arduino.h is a byte-for-byte match (all pin values) with the
  PR that Soldered Electronics itself participated in and endorsed as
  "our board." That is strong enough vendor confirmation that GPIO9 is a
  genuinely populated onboard push-button (not a copy-paste artifact or
  a repurposed strapping pin with no physical switch), especially given
  the ESP32-C6 boot-strapping note on GPIO9 ("must be HIGH for normal
  boot") is exactly the electrical behavior expected of a BOOT/user
  button wired to pull GPIO9 low when pressed - the standard ESP32-C3/C6
  BOOT-button pattern.

  Alias-collision check: build_boards.js (parseEsp32Consts/
  buildEsp32Board, ~L541-548) unconditionally appends spi_ss/spi_mosi/
  spi_miso/spi_sck/i2c_sda/i2c_scl capabilities to whichever GPIO number
  matches consts.SS/MOSI/MISO/SCK/SDA/SCL by exact declared value. In
  this file: SDA=6, SCL=7, SS=2, MOSI=3, MISO=4, SCK=5, TX=16, RX=17 -
  none of these equal 9. GPIO9 carries no other alias in this file
  besides USER_BTN. No collision found; no alias line needed deletion.

  No onboard NeoPixel was found in any source (product page, hardware
  docs, or the vendor-confirmed pins_arduino.h) - only a plain
  LED_BUILTIN on GPIO23 - so no section 7a NeoPixel capability action
  was warranted for this board.

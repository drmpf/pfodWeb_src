  RGB_DATA=18, RGB_BUILTIN=(RGB_DATA+SOC_GPIO_PIN_COUNT), LED_BUILTIN=RGB_BUILTIN (new rgbLedWrite API),
  and TX=43, RX=44. No BUTTON/BOOT alias is defined anywhere in this file.

Tagged:
- GPIO18 -> led_neopixel (+ digital_output, + pwm_output retained since it was already present).
  Confirmed via pins_arduino.h RGB_DATA=18 corroborated by the Unexpected Maker/Adafruit product
  pages ("Low Power RGB LED" feature) and independent web reports of GPIO18 NeoPixel data pin for
  this exact board. Not TX(43)/RX(44), so no TX/RX conflict.

Considered but NOT tagged:
- GPIO0 (BOOT/strapping pin, "Must be HIGH for normal boot" per existing pinNotes) - considered as a
  possible physical "user button" candidate because ESP32/ESP32-S3 dev boards commonly wire a BOOT
  button to GPIO0. However, no vendor source (product pages, esp32s3.com, Adafruit listing,
  pins_arduino.h) explicitly documents a physical BOOT or user button on the TinyS3, and
  pins_arduino.h defines no BUTTON/BOOT alias at all (unlike the RGB LED, which IS explicitly
  aliased). This is a deliberate no-guess decision, not a best-guess judgment call - there was
  no confirming evidence either way, and GPIO0's boot-strap role plus lack of documentation made
  it too risky to tag as a general-purpose button. Left completely untagged; a human reviewer with
  access to the schematic PDF (schematic-tinys3.pdf, linked from
  https://github.com/UnexpectedMaker/esp32s3) could confirm/deny an onboard BOOT button and its
  GPIO if desired.
- GPIO17 (RGB_PWR / NeoPixel power gate) - NOT reconsidered; this was already excluded from chipGpios
  by an earlier audit pass (pre-existing NOTE at top of board.json). Out of scope for this task, left
  untouched.

Summary of changes made: Tagged GPIO18 capabilities to ["digital_output","led_neopixel","pwm_output"]
in board.json (onboard NeoPixel data pin). No button was tagged - no confirmable onboard physical user
button was found in vendor documentation for this specific TinyS3 (S3) variant.

IMPORTANT DISCREPANCY NOTED (for human review)
------------------------------------------------
This directory's own pins_arduino.h (variants/esp32/esp32s3/
waveshare_esp32_s3_touch_lcd_146/pins_arduino.h) has
USB_PRODUCT "ESP32-S3-Touch-LCD-1.85-Box" and USB_PID 0x8287 - i.e. it
does NOT actually self-identify as "ESP32-S3-Touch-LCD-1.46" at all.
This looks like an upstream copy-paste/generation error in the variant
file set (spot-checked: the sibling waveshare_esp32_s3_touch_lcd_185_box
directory's pins_arduino.h also has yet another mismatched
USB_PRODUCT string, "ESP32-S3-Touch-LCD-2.1", and USB_PID 0x825B - so
none of these three files' embedded product strings can be trusted at
face value).
However, this directory's electrical pin layout (SCL=10, SDA=11,
TX=43, RX=44, SPI SS=34/MOSI=35/MISO=37/SCK=36) is IDENTICAL to the
sibling waveshare_esp32_s3_lcd_146 directory, which was independently
tagged earlier this session (GPIO6 button) using the SAME vendor GitHub
repo (waveshareteam/ESP32-S3-Touch-LCD-1.46) as source of truth. Given
the identical pinout and identical vendor source repo, GPIO6/GPIO7
PWR button/control assignment was judged to apply to this directory as
well. This is a judgment call bridging the mismatched embedded product
string - flagged here explicitly for a human reviewer to double check
if desired (e.g. by obtaining the actual 1.46 schematic PDF, which
returned 404 during this research pass).

PINS CONSIDERED BUT NOT TAGGED
--------------------------------
- GPIO7 (PWR_Control_PIN): output-only power-hold/enable line driven by
  firmware to keep the board powered on; not a button or LED. Not
  tagged - no guess made, this is clear from the source code function
  names and usage (digitalWrite HIGH to stay on, LOW to shut down).
- BOOT button: vendor docs (docs.waveshare.com) mention a "BOOT Button"
  exists but give no GPIO number for it, and no schematic could be
  fetched (404) to confirm. This is very likely the standard ESP32-S3
  GPIO0 strapping/boot pin, which is a chip-level auto-boot pin already
  excluded from user-taggable digital_input+button use by convention on
  every other board in this repo (see "pinNotes" -> GPIO0 "Must be HIGH
  for normal boot"). NOT tagged - left as a best-guess judgment call
  for a human: if confirmed to be plain GPIO0, standard project
  convention appears to leave strapping-pin BOOT buttons untagged, but
  this was not tagged pending explicit confirmation.
- Power Indicator LED / Charging Indicator LED: vendor docs explicitly
  describe both as automatic status indicators driven by the
  charging/power-management IC, not GPIO-driven / not user-controllable
  outputs. NOT tagged - no GPIO evidence exists because these are
  hardware-driven, not software-driven, so no capability tag applies by
  design (this is not a guess - the vendor documentation directly states
  these are non-programmable).
- No RGB/NeoPixel LED is mentioned anywhere in the sources consulted for
  this board. NOT tagged.
- TX/RX check: this board's TX=43, RX=44 (per pins_arduino.h). GPIO6 and
  GPIO7 do not conflict with TX/RX, so no TX/RX-reservation conflict
  applies to the GPIO6 button tag.

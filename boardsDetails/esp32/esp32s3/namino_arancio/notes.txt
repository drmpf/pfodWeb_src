namino_arancio - onboard button / LED research notes
======================================================

Sources consulted:
- https://namino.cc/ - Namino product family homepage; confirms Arancio is one of three ESP32-S3-WROOM-1U-N4R8 industrial boards (Bianco/Rosso/Arancio).
- https://namino.cc/hardware/ - General hardware page; lists "1 knob input and button" as an I/O feature but gives no GPIO pin numbers or schematic for onboard LED/button.
- https://namino.cc/products/boards/ - Board family overview; describes Arancio as "the board with analog inputs configurable in current/voltage only (0-10V/0-20mA)". No LED/button GPIO details.
- https://shop.namino.cc/products/namino-arancio - Shop product page; repeats "1 knob input and button" spec, no pin/schematic detail.
- https://github.com/namino-cc/examples (and /tree/main/Arduino) - Official Namino examples repo. Confirms folder "namino_arancio_blinkLed" exists.
- https://raw.githubusercontent.com/namino-cc/examples/main/Arduino/namino_arancio_blinkLed/namino_arancio_blinkLed.ino - IMPORTANT FINDING: this "blink LED" example redefines `#define LED_BUILTIN 1` as a channel index into the `namino_arancio` industrial-I/O library (`na.writeDigOut(LED_BUILTIN, ...)`), and the code comment/README says this drives "DIG OUT1 (digital output 1) - Side B - J15". This is an industrial PNP digital-output terminal on the board's screw-terminal side, driven over SPI through the board's secondary onboard microcontroller (the same secondary chip whose reset/boot-strap lines GPIO47/48 are already excluded from chipGpios per the existing pfodWeb NOTE in this board's pins_arduino.h/board.json). It is NOT a raw ESP32 GPIO pin and has no entry (and cannot have one) in chipGpios.
- https://github.com/espressif/arduino-esp32/pull/8582 (and /pull/8407) - Upstream PR adding the namino_rosso/namino_arancio board support to arduino-esp32. Reviewed PR description/comments: no mention of onboard status/power LED or button GPIO assignments beyond the generic "1 knob input and button" I/O spec already seen on the marketing pages.
- https://ipxchange.tech/evaluation-boards/namino-rosso-arancio-and-bianco-industrial-grade-esp32-development-boards/ - Third-party writeup; confirms ESP32-S3-WROOM-1U-N4R8, 4MB flash/8MB PSRAM, RS485/DIN-rail/USB-C, "1 knob input and button" - again no GPIO-level detail.
- Local file: variants/esp32/esp32s3/namino_arancio/pins_arduino.h - checked directly for LED_BUILTIN/BUTTON/NEOPIXEL/RGB aliases: NONE are defined anywhere in this file (confirmed by grep and by full read). This matches the upstream repo copy (also checked, same absence).

Pins considered but NOT tagged:
1. J10_enc_A, J10_enc_B, J10_sw (pins_arduino.h lines 194-196) - all three are literally defined as `= 0`, i.e. numerically identical to GPIO0 (which is already used on this board as SCL, per line 114/164 `J1_io0 = SCL` and `SCL = GPIO0`). There is no vendor documentation confirming these J10_enc_A/B/sw aliases correspond to a real, dedicated, wired-up onboard rotary-encoder push button on the Arancio variant specifically - grepping the sibling namino_bianco/pins_arduino.h for the same aliases (J10/enc/sw) found NO matches there either, so this is not even a pattern shared consistently across the family. Given the task's explicit instruction never to infer capability purely from pins_arduino.h alias names, and the "0" value being ambiguous/placeholder-looking (aliasing an already-assigned I2C pin), I made NO guess and did not tag this. This is a genuine open question for human review: is J10_sw a real button on some Namino variant using pin GPIO0, or is it just an unused placeholder define carried over between board variants that share a common header template?
2. "DIG OUT1 / Side B / J15" (the only officially-documented "LED" example for this board) - confirmed via the vendor's own blinkLed example to be an industrial PNP output channel routed through the board's secondary I/O microcontroller over SPI, not a native ESP32 GPIO at all. There is no chipGpios entry this could ever map to, so it is out of scope for GPIO capability tagging (not a "did not tag due to uncertainty" case - it structurally cannot be tagged).
3. No other candidate onboard LED (power/status/WiFi indicator) or onboard pushbutton (e.g. BOOT/reset button) tied to a specific GPIO could be confirmed via any vendor source, schematic, or datasheet found. (No public schematic PDF was located for Arancio specifically during this search.)

Summary of action taken: NO CHANGE. board.json and pins_arduino.h for namino_arancio were left untouched - no GPIO capability tags were added, because no onboard button or LED could be confirmed to be wired to a specific, taggable ESP32 GPIO via real vendor documentation.

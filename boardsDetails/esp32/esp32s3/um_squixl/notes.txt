um_squixl - dedicated-hardware pin-exclusion audit notes
=========================================================

Board directory: C:\ai\aicode\pfodWeb\variants\esp32\esp32s3\um_squixl
Chip: esp32s3. No board.json existed before this pass (chip-level default
at variants/esp32/esp32s3/board.json was the only config in effect).

Flagged by: fresh discovery sweep hit on
  static const uint8_t SDO = 46;
  static const uint8_t SDI = 41;
in pins_arduino.h, plus the existing SS=42/MOSI=46/MISO=41/SCK=45
declarations in the same file - all 4 GPIOs turned out to be part of one
dedicated onboard bus (see "IOMUX" below), not general SPI.

This is Unexpected Maker's "SQUiXL" - a battery-powered ESP32-S3 handheld
with a 4-inch 480x480 round-cornered RGB touchscreen, not a plain dev
board. NOTE: a sibling UM board "um_edges3_d" is being audited separately
this wave - deliberately did NOT assume any similarity between the two;
all reasoning below is SQUiXL-specific.

Reasoning per pin group
------------------------
- GPIO0: KEEP, tagged "button". Physical IO0/Boot button per CNX
  Software's hardware list, corroborated directly by firmware source
  (`pinMode(0, INPUT_PULLUP)` in main.cpp - a real runtime digitalRead,
  not just an at-boot strap). Tagged capabilities: ["digital_input",
  "button"] only, per the established policy (no digital_output/
  pwm_output alongside a button tag).
- GPIO1/GPIO2 (SDA/SCL): KEEP as general I2C. Carries several onboard
  chips (GT911 touch, IO expander, MAX1704X gauge, RV-3028-C7 RTC) but
  is also exposed externally via a STEMMA/Qwiic connector (CNX Software)
  for user expansion - I2C is inherently multi-drop and this matches the
  "general-purpose I2C without an exclusive onboard consumer stays kept"
  policy already used on other boards in this audit (e.g. m5stack_dial's
  Grove I2C).
- GPIO3: EXCLUDE. TP_INT - GT911 touch controller interrupt line
  (squixl.h: `TP_INT 3`).
- GPIO4-8, 9-14, 15-18, 21: EXCLUDE. RGB LCD data lines R0-R4/G0-G5/
  B0-B4 (UM_GFX.cpp PANEL_UM_480x480 struct, see source 5 above).
- GPIO38, 39: EXCLUDE. RGB LCD DE and PCLK (same struct).
- GPIO40: EXCLUDE. BL_PWM - LCD backlight PWM (squixl.h).
- GPIO41, 42, 45, 46: EXCLUDE. TMUX1574RSVR IO-mux lines shared between
  the microSD card's SPI bus and the I2S audio bus to the MAX98357A amp
  (squixl.h: `MUX_D1 41`, `MUX_D2 42`, `MUX_D3 45`, `MUX_D4 46`). These
  are exactly the 4 GPIOs this board's own pins_arduino.h used to alias
  as MISO/SS/SCK/MOSI(/SDI/SDO) - deleted those alias declarations
  entirely from pins_arduino.h (not just excluded in board.json) because
  build_boards.js unconditionally appends SPI-bus capabilities to any
  GPIO aliased as SS/MOSI/MISO/SCK/SDA/SCL/TX/RX in pins_arduino.h,
  regardless of what chipGpios says - leaving the aliases in place (even
  commented out, since the parser is comment-blind) would have silently
  re-leaked SPI capability tags onto these 4 excluded GPIOs. This was the
  specific critical check called out for this task and is why
  pins_arduino.h was edited as well as board.json.
- GPIO43: EXCLUDE. MAX1704X battery fuel-gauge interrupt/ALRT line
  (readme.md: "IO43 (FG Interrupt)").
- GPIO44: EXCLUDE. RV-3028-C7 RTC interrupt line (readme.md: "IO44 (RTC
  Interrupt)").
- IO-expander "virtual" pins (BL_EN, LCD_RST, TP_RST, SOFT_PWR, MUX_SEL,
  MUX_EN, HAPTICS_EN, VBUS_SENSE, SD_DETECT - squixl.h "EXP IO" block,
  values 0-11): NOT modeled at all, not a judgment call. These live
  behind the onboard I2C IO-expander chip, not on the ESP32-S3's own
  silicon pin list, so there is no chipGpios entry that could represent
  them (same structural situation as unphone9's TCA9555-routed LED_GREEN/
  LED_BLUE channels, see that board's own notes.txt for the identical
  reasoning pattern).

No alias-conflict issues found beyond the SS/MOSI/MISO/SCK/SDO/SDI one
already described above (SDA/SCL are the only aliases kept, and GPIO1/2
are intentionally kept available, so no contamination risk there).

Result
------
Created variants/esp32/esp32s3/um_squixl/board.json (full copy of the
ESP32-S3 chip-level default, chipGpios trimmed to only GPIO0 (tagged
"button"), GPIO1, GPIO2). Deleted the SS/MOSI/MISO/SDO/SDI/SCK alias
block from pins_arduino.h entirely (replaced with a plain-English
explanatory comment, no reproduced declaration text). Net effect: of the
31 GPIOs in the chip-level default, 28 are excluded as dedicated display/
touch/audio-mux/battery/RTC hardware, leaving only GPIO0 (button) and
GPIO1/GPIO2 (general I2C, also exposed via STEMMA/Qwiic) available in the
Designer's pin picker for this board - consistent with it being a
fully-integrated handheld device rather than a general-purpose dev board.

PINS CONSIDERED AND NOT TAGGED
-------------------------------
- GPIO0 (BOOT/flash-mode strap pin): This is the standard ESP32-S3 BOOT button,
  tied to GPIO0 per the DTR/RTS auto-reset circuit description found in source 5.
  However GPIO0 is ALREADY in this board's existing pin-exclusion list in board.json
  (used onboard as WS_LCD_G3, the ST7262 LCD's green-3 data line — see
  pins_arduino.h line 24 and the board.json header NOTE). Per task rules, pins
  inside an existing chip-level/board-level exclusion must NOT be re-added even if
  a button is confirmed on them. No guess made; left untagged and excluded exactly
  as before. No board.json edit made for this reason.
- EN/CHIP_PU (RESET button): hardware reset line, not a GPIO readable by firmware,
  so not taggable as a "button" capability under this scheme regardless. Not a
  chipGpios entry at all.
- CH422G expander pins (EXIO0-5, OD0/OD1 - TP_RST/LCD_BL/LCD_RST/SD_CS/DI0/DI1/DO0/DO1):
  these are behind an I2C IO-expander chip, not native ESP32-S3 GPIOs, so they have
  no corresponding chipGpios entry to tag in board.json regardless of function. Not
  a button or user LED anyway (backlight/reset/CS/isolated-IO functions only).
- DONE/CHG/PWR LEDs: confirmed across 3 independent sources as passive battery
  charge/power indicators wired to the CS8501 charge-management chip, not to any
  ESP32-S3 GPIO. Not user-controllable, not tagged.
- No WS2812/NeoPixel/RGB LED found anywhere in the fetched documentation for this
  specific 5.0" model (cross-checked per this session's known hallucination risk
  on Waveshare sibling-board pages) — none exists on this board, nothing to tag.

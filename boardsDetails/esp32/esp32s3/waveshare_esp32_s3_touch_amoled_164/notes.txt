PINS CONSIDERED BUT NOT TAGGED
-------------------------------
- No WS2812/RGB LED GPIO was tagged. Reason: no confirming evidence in the
  actual vendor wiki page content (source #1) despite an initial (rejected)
  search-summary claim to the contrary (source #5). This was a deliberate
  "no guess" decision, not a judgment call — if a human reviewer can find
  a genuine WS2812 pin definition in Waveshare's official demo firmware or
  schematic PDF, that would need to be re-verified and tagged separately.
- RST button: not tagged. It is the ESP32-S3's hardware EN/reset button
  (resets the whole chip), not a GPIO the firmware can read as a normal
  digital input, so it is not eligible for the "button" capability tag.
- Checked GPIO0 (BOOT/KEY_0 button) against this board's TX/RX pins
  (pins_arduino.h: TX=43, RX=44) — no conflict, GPIO0 is safe to tag.

WHAT WAS TAGGED
----------------
GPIO0 capabilities changed from ["digital_input","digital_output",
"pwm_output"] to exactly ["digital_input","button"], confirmed as the
onboard BOOT button per Waveshare's own wiki page (see source #1) and
matching this board's own pins_arduino.h `#define KEY_0 0`. No LED tag
applied (no confirmable onboard LED found).

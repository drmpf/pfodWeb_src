FINDINGS
1. Onboard LED: GPIO21 (LED_BUILTIN, D13, also GDI_BLK - the GDI connector's optional
   backlight-enable line). Confirmed via wiki.dfrobot.com/dfr1145/ pin table ("LED GPIO21")
   and cross-checked via the alternate URL alias for the same page. Confirmed to be a plain
   LED, not WS2812/NeoPixel - no source anywhere (wiki pages, blink-example pages, product
   description) mentions addressable/smart-LED functionality, and the blink example uses a
   single digitalWrite() to a single pin (no data-protocol timing), consistent with a plain
   LED. No source states active-high/active-low drive polarity - the blink example code
   toggles digitalWrite HIGH then LOW with no prose stating which state is "on". Per this
   project's no-guess policy (same outcome reached for dfrobot_firebeetle2_esp32c6 and
   dfrobot_firebeetle2_esp32c5's own LED_BUILTIN pins), NO led_high/led_low tag applied -
   left as an explicit unconfirmed item for human review. GPIO21 was already present
   (KEEP, not excluded) in the existing board.json from the prior GDI-exclusion pass.

2. Onboard button #1 - "Boot Key": GPIO0 (D9 in this board's pins_arduino.h). Confirmed via
   wiki.dfrobot.com/dfr1145/ pin table ("Boot Key GPIO0"), also referenced generically in the
   standard "hold BOOT, click RST, release BOOT" download-mode recovery procedure common to
   this vendor's guides. GPIO0 is simultaneously this chip's boot-mode strapping pin (chip-
   level board.json pinNotes already carries "Must be HIGH for normal boot" - left unchanged).
   Tagged capabilities -> ["digital_input","button"] (dropped digital_output/pwm_output),
   matching this repo's established convention for confirmed onboard BOOT pushbuttons
   (um_pros3 GPIO0, dfrobot_firebeetle2_esp32p4 GPIO35, dfrobot_firebeetle2_esp32c6 GPIO9,
   dfrobot_firebeetle2_esp32c5 GPIO28).

3. Onboard button #2 - "User Key": GPIO47 (D14 in this board's pins_arduino.h). Confirmed via
   wiki.dfrobot.com/dfr1145/ pin table ("User Key GPIO47", also phrased "47/D14 onboard
   button pin"), cross-checked via the alternate URL alias for the same page - a SECOND,
   dedicated user-accessible pushbutton distinct from the Boot Key. Not a strapping pin, no
   pinNotes entry needed. Tagged capabilities -> ["digital_input","button"] (dropped
   digital_output/pwm_output), same convention as GPIO0 above.

4. Battery voltage sense: no source consulted (wiki.dfrobot.com/dfr1145/ pages, blink-example
   guide pages, boards.txt) mentions any battery-voltage-detection pin or LiPo circuit for
   this SKU - out of scope, no change. (Unlike the ESP32-C6/C5 FireBeetle 2 siblings, this N4
   board's wiki pages gave no indication of an onboard battery-monitoring circuit.)

5. Alias-collision check (per task step 4, checked repeatedly this session): confirmed
   neither GPIO0 (Boot Key) nor GPIO47 (User Key) nor GPIO21 (LED_BUILTIN/GDI_BLK) is also
   aliased as SDA(1)/SCL(2)/SS(10)/MOSI(15)/MISO(16)/SCK(17)/TX(43)/RX(44) anywhere in this
   board's pins_arduino.h. GPIO21's only other alias is GDI_BLK (a backlight-enable output
   for the optional GDI display connector, not a shared-bus signal), which does not grant
   any bus capability via build_boards.js. No contamination found; no pins_arduino.h edits
   were needed for this pass.

6. GDI connector exclusion (GPIO3/7/9/12-14/18/38): unchanged from the prior pass - already
   correctly excluded from chipGpios in the existing board.json as dedicated,
   no-general-alias GDI display-connector-only signals (DC/RES/CS/SDCS/FCS/TCS/INT/BUSY_TE).

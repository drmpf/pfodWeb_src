PINS CONSIDERED AND NOT TAGGED
-------------------------------
- GPIO35 (WS_SYS_EN) and GPIO36 (WS_SYS_OUT) - together form the onboard "PWM/power" button
  circuit (SYS_OUT is pulled low when the button is pressed; SYS_EN is the power-hold output
  driven by firmware). This is a real, vendor-confirmed onboard button, not a guess. However,
  GPIO35 and GPIO36 both fall inside the ESP32-S3 octal-flash/PSRAM reserved GPIO33-37 range,
  which this board's board.json ALREADY excludes from chipGpios (no "33"-"37" keys present -
  see the existing NOTE comment at the top of board.json referencing GPIO4-8/15/38/41 exclusions;
  the 33-37 exclusion is the standard chip-level ESP32-S3 octal PSRAM/flash exclusion applied to
  every S3 board using octal PSRAM, e.g. WS8 = ESP32-S3R8/8MB PSRAM part on this board).
  Per task instructions, this pre-existing pin-exclusion must NOT be reversed just to add a
  button tag. Left untagged deliberately - flagging for human review in case a reviewer wants to
  special-case re-add GPIO35/36 for this board specifically.
- GPIO33 (WS_BUZZ) - onboard buzzer, not a button or LED, not a pfodWeb capability-tag candidate
  regardless; also falls in the same GPIO33-37 excluded range.
- No onboard LED (single-color, RGB, or NeoPixel) was found in any of the four sources above.
  Made NO guess/inference from pins_arduino.h naming (there is no LED-suggestively-named define
  in this board's pins_arduino.h anyway - only WS_BUZZ/WS_SYS_OUT/WS_SYS_EN, WS_LCD_*, WS_RTC_*,
  WS_QMI8658_*, none of which are LED candidates).

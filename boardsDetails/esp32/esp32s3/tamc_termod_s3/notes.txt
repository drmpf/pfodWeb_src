Pins considered but NOT tagged:
- GPIO48 (TFT Backlight / Arduino LED_BUILTIN alias): NOT tagged as an LED. Vendor docs
  explicitly identify GPIO48 as "TFT Backlight" (Selectable pins section: "JP2 is for
  selecting the TFT backlight pin... Set IO48 HIGH to turn on backlight"), i.e. a
  display-subsystem pin, not a standalone user-controllable status LED. It is already
  excluded from this board's chipGpios entirely (pre-existing pin-exclusion, part of the
  "GPIO10-14/18/48 dedicated onboard TFT display" note at the top of board.json) and is out
  of scope to re-add per task rules. This is a confident decision (not a guess) based on
  the vendor's own schematic/pin-assignment wording.
- Power indicator LED "D1": NOT tagged. Vendor schematic text states D1 is a fixed "3.3V
  power indicator LED" with no GPIO connection at all (wired directly across the 3.3V rail)
  - there is no GPIO to tag. Confident decision, not a guess.
- No other candidate LED pins were found anywhere in the vendor documentation. This
  confirms the existing pins_arduino.h comment ("This board has no NeoLED or any User LED")
  written during the earlier pin-exclusion audit pass.

Pin tagged:
- GPIO0 tagged ["digital_input","button"] - confirmed genuine onboard physical pushbutton
  via vendor's official Pin Assignment table ("GPIO0 | Button") and schematic text ("Simple
  setup for ESP32 S3 with buttons(IO0 and EN)"). Not a TX/RX conflict (board's TX=43,
  RX=44). This is the same IO0/BOOT-strap button also used for entering flash mode (per
  FAQ), consistent with the standard convention used elsewhere in this repo (e.g.
  alksesp32, deneyapkart, heltec_* boards) of tagging the genuine physical IO0 button as
  "button" despite it doubling as a boot-strapping pin.

Summary: Tagged GPIO0 -> button (digital_input + button). No LED/NeoPixel tag applied -
this board has no confirmable onboard user LED.

um_feathers2 (Unexpected Maker FeatherS2, ESP32-S2) — button/LED capability audit
Date: 2026-07-11

Sources consulted:
- https://feathers2.io/ — Official FeatherS2 product/docs page. Confirms the board has an onboard APA102 (DotStar) RGB LED, described as "The RGB LED (APA102) is powered by the second LDO. You need to enable the second LDO power via GPIO21 to be able to use the RGB LED." Confirms APA102 = two-wire (data+clock) protocol, NOT a single-wire NeoPixel/WS2812. Page text did not spell out the exact data/clock GPIO numbers or mention any onboard user button besides RESET/BOOT.
- https://unexpectedmaker.com/shop/feathers2-esp32-s2 — FeatherS2 product page (searched, general board feature summary: ESP32-S2, 16MB flash, 8MB PSRAM, Feather format). No additional button/LED GPIO detail beyond what feathers2.io gave.

- WebSearch "FeatherS2 GPIO0 boot button pin unexpectedmaker" — Confirms the only physical pushbutton pair on the board is RESET and BOOT; BOOT is wired to GPIO0, the standard ESP32 strapping/download-mode pin, used to enter bootloader mode (hold BOOT, tap RESET). This is a boot-mode strapping button, not a general-purpose app button.

No BUTTON or LED_BUILTIN alias defined anywhere in this file — no separate single-color LED exists on this board. TX = GPIO43, RX = GPIO44 (for reference; not relevant here since no tag candidates coincided with these).
- Local file /c/ai/aicode/pfodWeb/variants/esp32/esp32s2/um_feathers2neo/board.json (sibling board, NOT modified, read only for precedent) — same ESP32-S2 base; GPIO0 (BOOT) is present in chipGpios but left with plain digital_input/digital_output/pwm_output capabilities, i.e. NOT tagged "button" in this repo's existing convention for this vendor's boot button.
- Local file /c/ai/aicode/pfodWeb/variants/esp32/esp32/um_tinypico/board.json + pins_arduino.h (another Unexpected Maker board with an onboard APA102 DotStar LED, NOT modified, read only for precedent) — confirms this repo's established precedent: the APA102 data (GPIO2) and clock (GPIO12) pins are NOT tagged with any LED capability; only the DotStar's internal power-gate pin (APA_POWER, GPIO13) was excluded from chipGpios entirely. No "led_neopixel" or discrete RGB tag was applied to the two DotStar signal pins on that board.

Pins considered but NOT tagged, and why:
1. GPIO0 (BOOT button) — NOT tagged as "button". This is a real physical pushbutton, but it is wired as the ESP32-S2 boot-strapping pin (must be HIGH for normal boot, per existing pinNotes["0"] in board.json) and is documented by the vendor only as the download-mode/bootloader entry button, not a general user-input button. This repo's own sibling board um_feathers2neo (same MCU/vendor) already leaves GPIO0 untagged under the same reasoning — followed that established precedent. This is a deliberate no-guess decision, not a coin-flip judgment call: the vendor documentation gives no indication this pin is intended for general app use, and tagging a boot-strapping pin as a user button risks conflicting with existing pinNotes guidance.
2. GPIO40 (APA_DATA) and GPIO45 (APA_CLK) — NOT tagged. The onboard RGB LED is confirmed (feathers2.io) to be an APA102/DotStar device, which uses a two-wire (separate data + clock) protocol, unlike a NeoPixel/WS2812 which uses a single data wire. The task's allowed tag set only offers "led_neopixel" for "a single data pin driving one or more" addressable LEDs — this does not describe a two-pin APA102 device, and there is no "led_apa102"/two-wire tag in the allowed list. Tagging either pin alone with led_neopixel would misrepresent the hardware (it would drop the clock pin dependency), and the discrete-RGB tags (led_r_high/led_g_high/led_b_high) are defined for separate R/G/B GPIOs, not a data+clock addressable-LED bus, so they don't fit either. This repo has an established, directly-comparable precedent (um_tinypico, another Unexpected Maker APA102 board) where the data/clock pins were deliberately left untagged for exactly this reason. Followed that precedent — this is a considered decision based on the tag taxonomy not covering 2-wire addressable LEDs, not a guess. Flagging both pins here explicitly for human review in case a future tag (e.g. "led_dotstar" or similar) is added to the taxonomy.
3. GPIO21 (LDO_2_POWER) — not a candidate; already excluded from chipGpios in this board's board.json (pre-existing exclusion, out of scope) and confirmed by feathers2.io to be an internal power-enable line for the APA102's LDO, not a GPIO capability candidate.

Summary: NO CHANGE. No confirmable general-purpose onboard button and no LED matching an allowed single-wire/discrete-RGB tag definition were found; board.json was left untouched.

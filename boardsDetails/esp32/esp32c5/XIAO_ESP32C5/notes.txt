  Wiki, authoritative) - fetched. Confirmed:
  * "On the XIAO ESP32C5, the pin corresponding to BAT_VOLT_PIN is GPIO6,
    and the pin corresponding to BAT_VOLT_PIN_EN is GPIO26." Board uses
    "two 100K resistors for voltage division" to measure battery voltage
    up to ~3300 mV, read via analogReadMilliVolts() (factory-calibrated).
  * Official example code (quoted in full, confirms BAT_VOLT_PIN_EN is
    NOT purely internal/automatic - it must be actively driven by user
    code):
      pinMode(BAT_VOLT_PIN, INPUT);
      pinMode(BAT_VOLT_PIN_EN, OUTPUT);
      digitalWrite(BAT_VOLT_PIN_EN, HIGH);
      ...
      Vbatt += analogReadMilliVolts(BAT_VOLT_PIN);
    This differs from the task's cited EXCLUDE precedent (NeoPixel
    power-gate confirmed internal via vendor docs, driven automatically by
    library code) - here the enable line is only asserted in the user's
    own sketch, so pfodWeb should not hide it from the pin picker.
  * LED_BUILTIN: "corresponds to the L LED"; example code
    `digitalWrite(LED_BUILTIN, LOW); // LED ON` confirms active-low
    behaviour, consistent wording with the sibling XIAO_ESP32S3/
    XIAO_ESP32S3_Plus boards' existing "led_low" precedent (GPIO21 on
    those chips) for the same product family's USER_LED convention. Pin
    map also separately lists a "User Light_Yellow" LED on GPIO27,
    matching LED_BUILTIN=27 in pins_arduino.h.
  * Onboard user button: page documents only a "Reset / Boot Button"
    (Boot = GPIO28, standard ESP32 strapping/download-mode button); no
    dedicated general-purpose user button is documented - not tagged,
    consistent with the no-tag precedent on other esp32 boards for the
    same BOOT role (e.g. um_tinys3, XIAO_ESP32S3).

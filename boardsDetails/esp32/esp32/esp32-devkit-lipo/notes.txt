FINDINGS AND DECISIONS
-----------------------
TX1=33, RX1=25, TX2=19, RX2=18 ("Ext1 pin 8/9", "Ext2 pin 8/9"):
  KEEP (general purpose). Confirmed general-purpose GPIO header pins
  broken out on the board's own EXT1/EXT2 pin columns, matching the
  manual's board-layout photo. The TX1/RX1/TX2/RX2 #defines are just a
  naming convenience for wiring an external UART device to those header
  pins via Serial1/Serial2 - not a sign of fixed onboard hardware. No
  onboard consumer (radio module, SD card, display) was found anywhere
  in the sourced documentation. chipGpios entries for 18/19/25/33 left
  unchanged from the chip-level default.

GPIO18/19 also alias SCK/MISO (static const SCK=18, MISO=19 already
present in pins_arduino.h - default VSPI bus pins):
  Checked per the new "hidden bus alias" parser-collision instruction -
  build_boards.js unconditionally appends spi_sck/spi_miso capabilities
  for whatever GPIO equals the SCK/MISO consts, regardless of chipGpios.
  Since no exclusion was applied to GPIO18/19 (both stay KEPT as general
  GPIOs), this collision is a non-issue here - there's nothing to
  "silently contaminate" since we never intended to exclude these pins.
  Confirmed no onboard SPI device (SD card, display, radio) exists on
  this board that these default VSPI pins would need protecting from
  user reassignment for - they're just the chip's usual default VSPI
  pin choice, unused by any onboard peripheral.

Reset button (RST1): NOT a GPIO - hard-resets the module via EN. No
  button capability tag applies (section 7a n/a, not a pin at all).

Battery-charger LED ("CHARGING" silkscreen): driven directly by the
  charger IC's own status output pin, not by a chip GPIO. No
  LED_BUILTIN or equivalent alias exists in pins_arduino.h. No LED
  capability tag applies (section 7a n/a).

GPIO35 (BAT_SENS_E1) / GPIO39 (PWR_SENS_E1) - optional battery-voltage
  and external-power-present sense circuits:
  KEEP as plain analog-input-only GPIOs (matches playbook policy for
  battery/voltage-monitor analog pins - these are exactly the kind of
  reading pfodWeb's own UI is meant to display). NOT excluded because
  the manual explicitly states the sense function only activates if the
  user solders the corresponding jumper pad closed - it is OFF by
  default, so out-of-the-box these are ordinary ADC-only GPIOs (already
  correctly restricted to analog_input/digital_input only via the
  chip-level inputOnlyGpios list, since they're in the 34-39 input-only
  range). Added two informational-only pinNotes entries (no capability
  change) documenting the optional jumper-gated sense function, citing
  the manual. Exact jumper-to-pin mapping (BAT_SENS_E1 -> GPIO35 vs
  PWR_SENS_E1 -> GPIO39) is inferred from context (battery pin numbered
  lower than power-present pin, consistent with the WROVER sibling
  PDF's PWR_SENS_E1->GPI39 mapping) since the plain-WROOM manual states
  both pins together ("...on pins GPI35 and GPI39") without an explicit
  per-jumper table - flagged as an inference, not a directly-quoted fact,
  in case a future reviewer finds a source that states it more
  precisely.

SUMMARY
-------
No pin exclusions were warranted on this board. TX1/RX1/TX2/RX2 are
confirmed general-purpose EXT1/EXT2 header pins, not dedicated onboard
hardware. Created board.json (full copy of the esp32/esp32 chip-level
default, chipGpios unchanged) solely to add two informational pinNotes
entries for the optional, off-by-default battery/power-sense pins
(GPIO35/GPIO39) plus a `// pfodWeb NOTE:` research-trail comment citing
the sources above. No onboard button or LED GPIO was found, so section
7a (button/LED capability tagging) is not applicable to this board.
pins_arduino.h was left unmodified (no exclusion needed, so nothing to
delete).
